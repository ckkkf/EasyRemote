## 三、输入精度 FAIL 是我的扰动脚本造成的

为了制造画面变化，我写了个 `jiggle.ps1`：在光标当前位置上按半径 3px 的圆每 100ms 移动一次，持续 60s。

结果两次运行落点：

| 运行 | 目标 | 实际 |
|---|---|---|
| 第 1 次 | (400,300) | (404,298) |
| 第 2 次 | (400,300) | (403,296) |

**偏差正好在 jiggle 的圆周范围内（±3px）**。也就是说：注入把光标放到 (400,300)，随后 jiggle 的下一拍又把它移走了。

**这条 FAIL 是测量方法的问题，不是注入的问题。** agent-1 之前「+4/-2 系统性偏移」的结论，很可能也是同一个原因——它当时也在同一个扰动环境下跑的。

要把这条测干净，扰动必须**不碰光标**（例如让一个窗口自己动），或者输入验证与扰动在时间上分离。

## 四、顺带暴露的测试编排问题

静止桌面下目标端发完 1 帧就进入等输入，而主控还在编码 8 帧（约 2 秒），于是目标端超时 panic：

```
recv input: AgentError("no input received")
```

这是示例程序的时序假设（「静止桌面也会持续发帧」）不成立导致的，不是产品缺陷。修法：目标端等输入的超时应大于主控发帧耗时，或主控先发输入再发帧。
