# ER-110 生产 ConsentNotifier 与跨实例通知

## 目标与成熟度
网关不再依赖进程内全局 Hub：新增 signal.ConsentNotifier，通过共享 Bus 写跨实例绑定并投递 CONSENT_REQUIRED；cmd/gateway 与 PG+Redis 的 stack 显式装配，rendezvous 订阅总线投递到本机连接。成熟度：beta（Redis 跨实例；完整多进程矩阵见 ER-903/ER-900）。

## 需求与字段映射
- 通知消息：TypeConsentRequired，body={session_id, from}；目标 deviceID 由 Bus 频道路由。
- 绑定：SaveBinding(session, from, to, TTL=10min) 供对端实例读取。
- 装配：BuildGateway/NewWithStoreAndSessions 增加 notifier 参数，禁止隐式 devHub 兜底。

## 能力链
- gateway App.Notifier → signal.ConsentNotifier → Bus.Publish
- signal 实例：RedisBus.Subscribe → hub.DeliverLocal → WebSocket Conn
- stack/cmd：dev 内存用 hubNotifier；cmd/gateway 与 PG+Redis 用 RedisBus notifier
- tests：fake bus 单测 + 真实 Redis 两实例测试

## 当前证据
- A-01：cmd/gateway 未注入 Notifier；stack PG+Redis 分支不挂信令；devHub 是进程内全局。
- Bus 已有 Publish/Subscribe/SaveBinding。

## 设计与不变量
- Notifier 缺 Bus 直接报错，不静默成功。
- 绑定先写后发；投递失败返回错误（ER-111 用它 fail-closed）。
- 两个 gateway 各持 notifier、两个 signal 实例各订阅同一 Redis；目标设备在哪个实例，消息就由哪个实例投递。
- devHub 只保留给一体化内存开发；生产装配显式传入 Redis notifier。
