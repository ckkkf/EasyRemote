# ER-202 关闭传播：双方停止、票据撤销、reason/end

## 目标与成熟度
任一端主动结束 / 后台强制中断：服务端写 closed（reason/end），向双方投递 DISCONNECT，撤销共享票据键；客户端 1 秒轮询会话状态兜底，停止采集/输入。成熟度：beta。

## 需求与字段映射
- 关闭命令：POST /v1/sessions/close（GW-25，device），body session_id/reason，response SessionStateResult。
- 传播：signal.ConsentNotifier.NotifySessionClosed → Bus.Publish(TypeDisconnect) 给双方 + DeleteBinding + RevokeSession。
- 撤销键：er:revoked:session:<id>，TTL 2h；relay 注册票据时检查。
- 客户端：host_stream/ctrl_session 每 1s 读 /v1/connect/status，closed/failed/ended 立即退出。

## 能力链
- gateway close handler → session.Close → Closer
- adminapi.KillSession → SetSessionCloser
- signal RedisBus RevokeSession；relay RedisRegistry.IsRevoked
- Rust Target/Controller session_state 轮询
- tests：gateway/admin/signal；E2E 回归

## 当前证据
- A-06：关闭只改数据库，无事件/无票据撤销；客户端靠 10s 心跳或永久空推。
- relay 只验 HMAC/exp，会话关闭后旧票据仍可用。

## 设计与不变量
- 关闭是幂等命令；重复 close 不再改 reason/version。
- 双方都收到 DISCONNECT；绑定删除；撤销键跨实例可见。
- 旧票据在 relay 注册时被拒（共享 Redis）；无 Redis 的开发中继不具备撤销能力，不得用于生产。
- 状态轮询是兜底，不替代事件；1s 内收敛，满足 3s 要求。
- 关闭失败（传播/撤销）要可观察：后台返回错误；网关记录错误但状态仍 closed，客户端轮询兜底。
