# ADM-API-03h 会话错误码时间线（缺口卡）

> 状态：**未开始**（缺口卡；ADM-API-03g 复核登记）
> 来源：`docs/spec/pages.md` A8（行 240-242「错误码时间线」）

## 缺什么

会话详情目前只展示**状态时间线**（创建 / 结束 + 原因）。spec 要求的"错误码时间线"需要：

1. 服务端按会话记录错误事件（错误码、发生时间、来源端、是否可重试）；
2. 客户端/网关在错误发生时上报（或网关在返回错误信封时按 session_id 落库）；
3. 时间线与质量采样对齐展示。

## 为什么不能现在做

服务端没有任何"会话级错误事件"存储：错误只出现在 HTTP 响应里，且大多数错误没有 session_id 上下文（例如授权失败时还没有会话）。直接拼接"看起来像时间线"的数据就是伪造。

## 建议拆分

- ADM-API-03h1：`session_errors(session_id, code, name, ts, source)` 表 + 网关在已知 session 的错误路径落库。
- ADM-API-03h2：详情页时间线合并状态事件与错误事件（按时间排序）。

## 验收提示

必须证明"每条错误时间线都对应一次真实错误返回"，并能用 trace_id 关联。
