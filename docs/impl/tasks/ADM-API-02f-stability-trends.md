# ADM-API-02f 稳定性指标与趋势图（缺口卡）

> 状态：**未开始**（缺口卡；由 ADM-UI-00b 复核登记）
> 来源：`docs/spec/pages.md` A2（行 204-208）、A7（行 234-238）、A8（行 240-242）、PRD §6.3.1（行 577-583）

## 缺什么

1. **稳定性组**：会话异常中断率、客户端崩溃率、重连成功率 —— 服务端没有对应事件源（异常中断需要会话结束原因分类，崩溃/重连需要客户端上报）。
2. **建连成功率 / P2P 命中率 / 帧率达成率**：需要建连埋点与档位目标值，当前采样里没有"是否成功建连"和"目标帧率"。
3. **趋势图**：24h/7d/30d 曲线需要按时间桶聚合接口 + 图表库（Recharts 未引入）。
4. **A7 会话行**：延迟 / 链路 / 结束原因列需要会话级链路信息（relay vs p2p、结束原因枚举）。

## 为什么不能现在做

用推导值或 0 值填充会直接违反 AGENTS §3.2（禁止虚假实现）。任何一项都需要先定义事件与口径，并由负责人确认指标定义（例如"异常中断"的判定条件）。

## 建议拆分

- ADM-API-02f1：会话结束原因枚举 + 异常中断率口径（含 session.reason 规范化）。
- ADM-API-02f2：建连埋点（success/failure + 链路类型）与 P2P 命中率。
- ADM-API-02f3：按时间桶聚合接口 + 前端趋势图（引入 Recharts）。

## 验收提示

每项都要有"数据来自真实执行点"的证据（事件写入点 + 聚合查询 + 前端渲染测试），不得用客户端计时器或健康检查代替。
