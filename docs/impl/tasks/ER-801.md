# ER-801 分页/筛选/排序下沉存储层（部分）

## 目标与成熟度
store.Page 增加 Query/Sort/Desc/Status；Memory/PG 对账号/设备/会话实现过滤与排序；adminhttp 解析 limit/offset/q/sort/desc/status；web-admin 用户页改为服务端分页，不再先截断再客户端分页。成熟度：beta（设备/会话/审计前端仍部分客户端处理，total 为推导值）。

## 需求与字段映射
- Page：Limit/Offset/Query/Sort/Desc/Status。
- adminhttp parsePage：limit≤500，offset≥0，q/sort/desc/status。
- adminapi ListUsers/ListDevices/ListSessions 接收 Page。
- 用户页：api.users({limit,offset,q,status})；行直接来自服务端。
- 兼容：旧调用 Page{Limit} 行为不变。

## 能力链
- adminhttp → adminapi → store Memory/PG
- web-admin api/users 页面

## 当前证据
- 旧实现 ListUsers/Devices 固定 200/500，前端过滤+slice，属于客户端分页。
- Store Page 无过滤/排序。

## 设计与不变量
- 排序字段白名单，禁止 SQL 拼接用户输入。
- limit 上限 500；offset 非负。
- 过滤/排序必须由存储层执行；前端不得对已截断结果分页。
- PG 与 Memory 语义一致（storetest/单测）。
