# ER-604 ABR 输入扩展：吞吐/缓冲/编码队列

## 目标与成熟度
ABR 决策纳入实测吞吐、播放缓冲、编码队列，并保留丢包/RTT/发送队列；用确定性属性测试保证档位边界/单次变化上限。成熟度：beta（吞吐/编码队列尚未由反馈报文实测，缓冲用发送队列代理）。

## 需求与字段映射
- LinkFeedback 增加 throughput_kbps、buffer_ms、encode_queue。
- severe：loss>8 或 queue>200 或 buffer>300 或 encode>8。
- mild：loss>2 或 queue>80 或 rtt>250 或 buffer>120 或 encode>4 或 throughput<当前码率×80%。
- healthy：loss<1、queue<40、rtt<120、buffer<60、encode<=1、throughput>=当前码率×90%（0=未知放行）。
- 既有严重单周期降两档、轻度两周期、健康 3 周期升档保持不变。

## 能力链
- FeedbackReport → LinkFeedback → AbrController
- tests：低吞吐阻止升档、缓冲严重、2000 步属性

## 当前证据
- A-11：ABR 只看 loss/rtt/queue；无吞吐/缓冲/编码队列。
- 无属性测试。

## 设计与不变量
- 任何单次决策：降档最多 2 级、升档最多 1 级、索引不越界。
- 吞吐未知(0)不得当作拥塞或健康；只做放行。
- 缓冲/编码队列超阈值必须参与降档。
- 所有阈值常量化，不散落魔法值（沿用原常量需注释）。
