# ER-011 移除 response:any 并生成三端 DTO

## 目标与成熟度
把 `docs/spec/contract.yaml` 里所有完成态 `response: any` 收敛为具体类型（文件下载明确为 binary 字节流），由生成器产出 Go/TS/Dart DTO，并用字段级测试证明每个端点都有三端结构。成熟度：disabled → beta（DTO 与契约完成；客户端全面改用生成 DTO 归 ER-014）。

## 需求与字段映射
| 端点 | response 类型 |
|---|---|
| GW-01 / GW-09 / GW-20 | OkResult |
| GW-02 | LoginResult |
| GW-03 | DeviceListResult{devices:list<DeviceItem>} |

- 字段来源：`docs/spec/contract.yaml` types 段；所有字段 snake_case。
- 生成物：`server/internal/contract/types_gen.go`、`web-admin/src/contract.ts`、`client/lib/contract.dart`。

## 能力链
- 契约：types + endpoint response
- 生成器：`scripts/gen-contract.mjs`（map<X> 统一为 string 键 → X 值）
- 服务端：gateway handler / files / email / assist / config / appconfig.Public 全部返回 contract 类型
- 客户端/后台：生成 DTO 已产出；运行时 JSON 未变（客户端仍用动态解析，ER-014 切换）
- 测试：`scripts/tests/contract-response.test.mjs`

## 当前证据
- 修改前 18 个端点 `response: any`；gateway 大量 `map[string]any{"..."}` 响应。
- `appconfig.Public` 返回嵌套 map；`fileDTO` 返回 map。

## 设计与不变量
- 完成态零 `any`；binary 是唯一非 JSON 响应，必须在契约注释里写明 octet-stream。
- `map<X>` 语义固定为字符串键；三端生成一致（Go map[string]X / TS Record<string,X> / Dart Map<String,X>）。
- 服务端响应必须使用生成类型，禁止再新增 `httpx.OK(map[string]any)` 响应（FORBIDDEN 扫描覆盖）。
- 可选字段 omitempty；空字符串时间等行为保持现有 JSON 形状（本卡不改变线上字段值）。
