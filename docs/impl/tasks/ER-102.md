# ER-102 删除 host_stream 自动 consent，只认本地决策

## 目标与成熟度
生产被控流（host_stream）收到会话后不再自动同意：必须等待本机 UI 经 FFI 发出的 decision；30 秒无决策=拒绝；远程/旧会话无法决策。成熟度：beta（生产流闭环；一次性 serve_host 与完整关闭语义分别在 ER-900/ER-202 收口）。

## 需求与字段映射
- 安全红线：跨账号连接必须由被控端本机显式接受；任何核心/后台/主控都不得代替。
- ConsentBroker：session_id / controller_label / seconds_left / decision(accept|reject|timeout)。
- FFI：
  - er_host_pending_consent(host_id) → {ok, session_id, controller_label, seconds_left}
  - er_host_decide_consent(host_id, session_id, accepted) → {ok} / {ok:false}
- Flutter：HostService 每 500ms 轮询 pending → ConsentController；决策流回调写回 FFI；设备页监听 controller 弹 ConsentDialog。

## 能力链
- Rust：host_stream.rs + host_consent.rs（Mutex/Condvar 闸门）
- FFI：host.rs 两个新导出
- Flutter：HostService 轮询/决策；ConsentController/ConsentDialog
- UI：DeviceListPage 展示弹窗
- tests：Rust 3 条 + Dart 6 条

## 当前证据
- 原 host_stream 在 wait_for_session 后直接 target.consent()，任何主控请求都会被接受（A-02）。
- 客户端没有 pending 查询/决策入口。

## 设计与不变量
- 无本地决策时 wait() 只能超时返回 false；代码中不存在自动 true 分支。
- decide(session) 只对当前 pending 生效；不匹配返回 false，状态不变。
- 超时/拒绝必须调用 target.reject()，不能留下 authorized/requested 僵尸。
- stop 时清空 broker 并唤醒等待方（返回 Err，流退出）。
- 决策只能来自本机 FFI 调用；网络消息不能直接调用 decide。
- remote_host 在台账中升为 experimental（开发可验证），发布构建仍关闭。
