# ER-002 自动启动真实 E2E 测试环境，禁止缺 env skip

## 目标与成熟度
用 Dart harness 在测试内自动构建/启动 stack + relay，健康检查就绪后运行真实 FFI E2E，结束后杀进程并释放端口；两条现有 E2E 不再因 ER_GATEWAY_URL / ER_RELAY_ADDR 缺失而 skip。成熟度：experimental → beta（本机 macOS 真实通过；Windows/Linux 桌面矩阵见 ER-900）。

## 需求与字段映射
- N/A（不改 HTTP/协议字段）。
- 复用 `server/cmd/stack`（内存存储 + 信令）与 `server/cmd/relay`（UDP 中继）；开发密钥走 `config.Secret()` 的 development 默认。

## 能力链
- harness：`client/test/support/e2e_services.dart`（repo 探测 → go build → 随机端口 → 启动 → health/log 就绪 → stop）
- E2E：`client/test/host_link_test.dart`、`client/test/session_e2e_test.dart`（去掉 env skip，setUpAll 启动）
- 自测：`client/test/e2e_services_test.dart`（`TestE2EHarnessStartsAndStopsServices`）
- gate/CI：flutter-test 步骤支持平台排除桌面 E2E 标签；CI 增加 Go 环境

## 当前证据
- 两个 E2E 在 `Platform.environment['ER_GATEWAY_URL'] == null` 时 print skip 并 return（不算失败）。
- 手工验证：`/tmp/er-e2e-bin/{stack,relay}` + `ER_GATEWAY_URL/ER_RELAY_ADDR` 时两条 E2E 全部通过（见 evidence 手工日志）。
- native.dart 构造参数被上一轮 lint 改写为 dynamic，E2E 暴露 `DynamicLibrary has no lookupFunction`；本卡修复为显式类型。

## 设计与不变量
- 端口随机（TCP/UDP 分别 bind 0 拿到空闲端口），不得硬编码 18090/29000。
- 就绪判定：stack 轮询 `/healthz` 200（100ms 间隔，10s deadline）；relay 等日志出现 `relay listening on`。禁止固定 sleep 作为唯一协调手段。
- 启动失败、进程提前退出、超时都抛异常并附日志尾部 → 测试失败，不 skip。
- stop：SIGKILL + 有界等待 exitCode；再次 stop 幂等；端口可重新 bind 证明释放。
- 若开发者显式提供 ER_GATEWAY_URL/ER_RELAY_ADDR，则复用外部服务且不启动本地进程（仍不 skip）；未提供则自启。
- 桌面 E2E 打 `e2e-desktop` tag；Linux CI 排除（无显示/无 FFI），macOS/Windows 矩阵由 ER-900 负责；harness 自测不带 tag，全平台运行。

## 完成状态（2026-11-22）
- 完成：两条 E2E 不再 skip；harness 自测 `TestE2EHarnessStartsAndStopsServices` 通过；`flutter test --concurrency=1` 62 passed；`bash scripts/gate.sh` PASS。
- 过程中发现并修复三个真实阻塞（否则 E2E 不可确定性通过）：
  1. 主控在 authorized 前取票据 → 403（conductor 增加 `wait_authorized` 有界等待）。
  2. 中继注册无 ACK：等待握手期间重发注册 + 自己的握手包。
  3. 先发出的握手在对端注册前被丢弃 → 收到对端后补发自己的握手。
- 归属说明：1/2 的最终形态属于 ER-201（事件驱动）与 ER-504（弱网/重连）；本卡只做让 E2E 可确定性通过的最小实现，后续卡必须替换轮询/补齐 ACK。
- 并行 flaky 根因：多个 suite 同时构建/启动真实服务，抢 CPU 与端口；gate/CI 统一 `--concurrency=1`。
