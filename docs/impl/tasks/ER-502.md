# ER-502 P2P 候选/STUN/打洞与 Relay 回落

## 目标与成熟度
实现 host 候选收集、STUN Binding 查询、带会话 token 的 UDP 打洞、3 秒内失败回落 Relay。成熟度：experimental（模块+测试完成；尚未接入会话编排/信令候选交换，见 ER-502a）。

## 需求与字段映射
- CandidateKind：Host/ServerReflexive/Relay；Candidate{kind,addr}。
- P2PConfig：session_id、16B token、timeout。
- STUN：Binding Request/Response，XOR-MAPPED-ADDRESS（IPv4）。
- Link：P2P{socket,peer} | Relay。
- probe/ack 魔数 ERP2P1 + token + session_id，防任意 UDP 注入。

## 能力链
- er-transport::p2p gather_host_candidates/stun_query/punch_candidate/select_link
- tests：STUN 映射、loopback 打洞、失败回落
- 缺口：未接 signalling TypeCandidates 与会话传输选择

## 当前证据
- A-09：只有 Relay，无候选/P2P/STUN；无链路类型可观测。
- 现有 signal TypeCandidates 转发可用，但客户端未使用。

## 设计与不变量
- 无 ACK 不打洞成功；token/session 不匹配一律丢弃。
- 全部候选失败在 timeout 内回落 Relay（不会无限等）。
- STUN 响应必须匹配服务器地址与事务；仅接受 IPv4 XOR-MAPPED。
- 不因 P2P 成功绕过加密/授权；传输只负责链路。
