# ER-201 双方数据面 ready 后才 Activate

## 目标与成熟度
authorized 不等于 active；只有主控与被控都完成握手并上报 ready，状态机才进入 active。成熟度：beta。

## 需求与字段映射
- store.Session 增加 ready_controller / ready_target（bool）；PG 迁移幂等加列。
- session.Command 增加 ready；Command.DeviceID 用于判定会话方。
- GW-24 POST /v1/sessions/ready（auth device，response SessionStateResult）。
- 前端/核心：Rust Gateway.mark_ready；TargetAgent/ControllerAgent 封装；host_stream、serve_host、conductor、ctrl_session 在 finish 成功后调用。

## 能力链
- Rust 握手完成 → POST /v1/sessions/ready（带设备凭证）
- gateway handler：requireDevice 判定会话方 → session.Ready
- 状态机：单方 ready 保持 authorized；双方 ready 且窗口有效 → active
- tests：session 单测 + HTTP 端点 + E2E 回归

## 当前证据
- A-05：active 无生产写入；客户端把 authorized 当已连接。
- 旧 Activate 只要求 authorized，不校验双方数据面。

## 设计与不变量
- ready 只对会话双方开放；非会话方 403。
- 授权窗口过期后 ready 直接关闭会话并返回 SESSION_AUTH_WINDOW_EXCEEDED。
- 重复 ready 幂等，不改 version。
- Activate 仍要求双方 ready；authorized 单独不产生 active。
- 任何一方 ready 失败不影响另一方；最终由窗口/关闭收敛。
