# ER-400 统一 RuntimeConfig

## 目标与成熟度
客户端端点（gateway/signal/STUN/relay/WebTransport/TLS）统一由服务端 /v1/config 下发；发布代码不再烧本机地址；生产必须显式 HTTPS 且不得 localhost。成熟度：beta（Rust 仍通过 FFI 参数接收端点，未自行拉配置）。

## 需求与字段映射
- contract RuntimeEndpoints：gateway_url、signal_url、relay_addr、stun_url、webtransport_url、tls_required。
- ClientRuntimeConfig.endpoints。
- env：ER_PUBLIC_GATEWAY_URL / SIGNAL_URL / RELAY_ADDR / STUN_URL / WEBTRANSPORT_URL / TLS。
- Flutter：GatewayClient.loadRuntimeConfig（/v1/config，无需登录）；gatewayURL/signalURL/relayAddr 只读 getter。

## 能力链
- appconfig.RuntimeEndpointsFromEnv → ClientRuntimeConfig.Public
- GatewayClient → 页面（session/host）读取；空 relay 拒绝启动被控/画面
- tests：Go 端口/生产校验；Node 扫描无 localhost；Flutter analyze/test

## 当前证据
- client main 默认 127.0.0.1:8080；session/device/self-test 硬编码 18090/19000；后台无端点配置。

## 设计与不变量
- 运行时配置优先于构建期 baseUrl；空值不回落 localhost。
- 生产缺省/HTTP/localhost 直接报错（服务端配置校验）。
- 页面在 relay 为空时明确失败，不启动半工作能力。
- 发布代码扫描 client/lib 与 er-client/src 无 127.0.0.1/localhost/18090/19000。
