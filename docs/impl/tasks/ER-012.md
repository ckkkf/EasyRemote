# ER-012 Handler method guard 与统一 405

## 目标与成熟度
把 ER-010 的 RouteSpec 变成运行时行为：所有已声明路由的错误 HTTP method 统一返回契约错误信封 405（含 Allow 头），handler 不再自己解释 method。成熟度：disabled → beta（精确路径全覆盖；带参数子路由由 ER-013 登记后纳入）。

## 需求与字段映射
- 错误：新增 `SRV_METHOD_NOT_ALLOWED=700012`（docs/spec/error-codes.md）→ 生成 Go/Rust 常量；HTTP 405。
- 响应信封：`{code:700012,name:"SRV_METHOD_NOT_ALLOWED",message,retryable,trace_id}` + `Allow` 头。
- 路由声明：沿用 `httpx.RouteSpec`（method/path/auth）。
- 契约修正：GW-08/GW-10/GW-19 实际为只读 GET（客户端/核心均按 GET 调用）；新增 GW-21 GET /v1/files 列表（原实现存在但未登记）。

## 能力链
- 契约：contract.yaml（method + response）→ 生成物
- 中间件：`server/internal/httpx/methodguard.go`
- 装配：gateway/adminhttp `Routes()` 用 MethodGuard 包住 mux
- 测试：gateway/adminhttp 表驱动 + 真实服务集成

## 当前证据
- 旧 handler 大多不校验 method：错误 method 会进入业务逻辑（A-18）。
- GW-08/GW-10/GW-19 契约写 POST、实现/客户端是 GET（A-17 的一部分）。
- GET /v1/files 列表未登记。

## 设计与不变量
- 精确路径匹配：声明路径的错误 method 一律 405；未声明路径仍走 404 信封。
- Allow 头按字典序列出契约允许的方法（同路径多方法正确）。
- 405 必须走 `httpx.Err`，保留 code/name/message/retryable/trace_id。
- 子路径（`/v1/files/{id}` 的 GET/DELETE/ticket）暂不在 RouteSpec 中，由 handler 现有逻辑处理；ER-013 登记后自动纳入。
- 不允许 handler 内再写一套 method 判断作为唯一防线。
