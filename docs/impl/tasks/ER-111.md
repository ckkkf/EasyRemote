# ER-111 notifier 缺失/投递失败/目标离线时请求 fail-closed

## 目标与成熟度
建会话前证明目标在线；生产（注入 Presence）下 notifier 缺失或投递失败必须清理会话并返回明确可重试错误，绝不返回假 requested。成熟度：beta。

## 需求与字段映射
- 错误：CONN_DEVICE_OFFLINE（200002，HTTP 400，retryable=false）。
- Presence 接口：Online(ctx, deviceID) (bool,error)；signal.Presence 本地 Hub 优先、跨实例走 Bus.IsOnline。
- Notifier：signal.ConsentNotifier（ER-110）。

## 能力链
- gateway.App.Presence / Notifier（显式注入）
- cmd/gateway：REDIS_URL → Bus + Presence；生产缺 REDIS_URL 拒绝启动
- cmd/stack PG+Redis：Bus/Hub/Presence/Notifier 全装配；生产缺 REDIS_URL 拒绝启动
- dev 内存 stack：Presence=nil（显式开发，不用于生产）、notifier=devHub

## 当前证据
- 原 handler 忽略 NotifyConsentRequired 错误，目标离线也返回 requested（A-01）。
- cmd/gateway 未注入 notifier；生产缺 Bus 仍启动。

## 设计与不变量
- Presence 非空：先判在线；离线/查询失败 → CONN_DEVICE_OFFLINE，不建会话。
- 建会话后 notify 失败：关闭会话（不留 requested）并返回 CONN_DEVICE_OFFLINE。
- notifier 缺失 + Presence 非空：同上 fail-closed。
- Presence 为 nil 仅用于内存一体化开发；生产装配必须注入（且缺 Bus 启动失败）。
- 不清除旧错误语义：成功在线且投递成功仍返回 requested，由授权流程推进。
