# ER-000 能力成熟度台账与未闭环能力禁用

## 目标与成熟度
建立唯一的能力成熟度台账（生成三端常量），让未闭环能力在发布构建中 **fail-closed**：远程控制（experimental）仅开发构建可见，被控共享/隐私屏/防休眠/剪贴板（disabled）任何构建都不可用，文件传输（experimental）发布构建隐藏入口。
before：设置开关/入口全部可点，被控默认自启且无本地授权；after：入口按台账能力门显示，发布构建不可绕过。

## 需求与字段映射
- 能力台账：`docs/spec/capabilities.yaml`（本卡新增，唯一来源）。
- HTTP 接口：本卡不改接口。GW-18 `/v1/config` 的 response 仍为 `any`，仅在 `data.config.capabilities` 增加只读布尔表，字段由 `docs/spec/capabilities.yaml` 生成；`contract.yaml` 仅补注释，生成物不变 → 字段映射 `N/A`（待 ER-011 定型）。
- 本机偏好 `allow_control`：默认/缺字段 = false（`docs/spec/pages.md:145`「允许被远程控制（总开关）默认关」）。
- 隐私屏（`pages.md:148`）、防休眠（`pages.md:151`）、文件传输（`pages.md:150`）、剪贴板（`pages.md:149`）的开关状态必须来自台账与真实实现，不得只写 prefs。

## 设计与不变量
- 成熟度取值：disabled / experimental / beta / stable。
- 可用性：disabled 永不可用；experimental 仅非发布构建；beta/stable 可用；未知能力**按不可用处理**。
- 发布构建（`kReleaseMode`）不读取任何偏好/环境覆盖；不存在 debug 开关能把 experimental 带进发布包。
- 服务端策略只能「加锁」：客户端 AND 服务端 disabled 集合，服务端返回 enabled=true 不能解锁客户端未成熟能力。
- `allow_control` 缺字段/脏数据 → false；本卡不实现授权弹窗，因此 `remote_host` 直接 disabled。
- 不删除入口所依赖的真实代码；只是不暴露入口，回滚 = 调整台账成熟度并重新生成（不得回滚到 fail-open）。

## 先写的失败测试
- `TestIncompleteCapabilityIsDisabled`（Dart）：release 下 remote_control/file_transfer 不可用；disabled 能力在 debug 也不可用；偏好不得覆盖。
- `TestUnknownCapabilityFailsClosed`：未登记 key 返回不可用。
- `TestDisableListOnlySubtracts`（Go）：`ER_CAPABILITY_DISABLE` 只做减法，`ER_CAPABILITY_ENABLE` 不能打开未成熟能力。
- `TestAllowControlDefaultsOff`（Dart）：默认与缺字段均为 false。
- `TestIncompleteCapabilityIsDisabled`（Go）：所有非 stable 能力在 `capability.Public()` 中为 false；`ER_CAPABILITY_ENABLE` 不能打开。
- `TestUnknownCapabilityFailsClosed`（Go）：未登记 key 不可用。
- UI：设置页隐私屏/防休眠开关 `onChanged == null` 且显示「未接入」；发布构建能力门不渲染连接入口（单元级能力门覆盖）。
