# ER-101 C18 本地授权 Controller 与授权弹窗

## 目标与成熟度
被控端本地出现授权请求时，由唯一 controller 管理 30 秒倒计时与接受/拒绝；超时等价拒绝；远程/旧会话无法替用户决策。成熟度：beta（controller + UI + 测试完成；真实信令事件接入在 ER-102）。

## 需求与字段映射
- docs/spec/pages.md C18：展示控制者信息、30 秒倒计时、接受、拒绝；超时=拒绝；只能被控端本机决定。
- ConsentRequest：session_id / controller_label / requested_at / expires_at。
- ConsentDecision：session_id / accepted / reason（accepted|rejected|timeout|superseded）。
- 信号桥接字段在 ER-102 接入（本卡不伪造来源）。

## 能力链
- UI：consent_dialog.dart（控制者、倒计时、接受/拒绝）
- domain：consent_controller.dart（状态机、Timer、决策流）
- signal：ER-102 把 CONSENT_REQUIRED 投给 controller
- tests：controller（fakeAsync）+ widget

## 当前证据
- ER-102 前 host_stream 收到会话直接 consent（自动同意），没有本地决策入口。
- 客户端没有授权弹窗/倒计时/决策流。

## 设计与不变量
- 同一时间最多一个 pending；新请求到达时旧请求按 superseded 拒绝，不允许静默覆盖。
- 只有当前 pending 的 session_id 能决策；其他 id 返回 false 且不产生决策（防远程/旧会话注入）。
- 倒计时由 Timer 主动推进，超时主动产生 rejected 决策并清空 pending；不依赖下次交互。
- 决策流只发一次；controller dispose 必须取消 Timer 并关闭 Stream。
- UI 只是 controller 的渲染层，不持有会话真相、不自行计时。
