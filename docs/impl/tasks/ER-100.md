# ER-100 allow_control 默认关闭与旧数据迁移

## 目标与成熟度
“允许被控”默认关闭；旧版本没有 version 字段的 allow_control=true 视为历史默认值，迁移为 false；偏好关闭或能力未接入时 HostService 在加载 FFI 之前拒绝启动。成熟度：beta。

## 需求与字段映射
- docs/spec/pages.md C13：允许被远程控制（总开关）默认关。
- Preferences JSON：新增 version=2；version<2 或缺失时 allow_control 一律 false；version>=2 的显式 true 保留。
- host_policy.hostBlockReason：prefs.allowControl=false 或 capability remote_host 不可用 → 拒绝。

## 能力链
- UI：settings/device_list 已按能力门禁用开关（ER-000）
- domain：Prefs 迁移 + host_policy
- host controller：HostService.prepare/start 在 _load() 前调用门禁
- tests：prefs/host_policy

## 当前证据
- ER-000 已把默认值改 false，但没有 schema 版本：旧快照里的 true 会被当成用户同意。
- HostService.prepare/start 之前无门禁，任何直接调用都能绕过 UI 启动被控。

## 设计与不变量
- 迁移只发生一次：toJson 始终写 version=2；无 version 的旧文件 allow_control 强制 false，其它偏好保留。
- HostService 的拒绝必须是 StateError 且在 FFI 加载之前；UI 隐藏不是唯一防线。
- 服务端“目标离线时请求 fail-closed”属于 ER-111（presence/notifier），本卡不改变 HTTP 语义，避免破坏 API-only 会话流程。
