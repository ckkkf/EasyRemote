# ER-501 可靠注册 ACK 与 UDP 分片修复

## 目标与成熟度
注册必须收到中继 ACK 才算成功；注册等待期间先到的数据要缓存；分片载荷限制在 1200B 避免 IP 分片；分片数有上限，防大分配。成熟度：beta。

## 需求与字段映射
- 帧类型：FRAME_REGISTER_ACK=4；ACK body 以 ERACK1 魔数开头。
- 客户端：register 重发最多 3 次、每次等 ACK 500ms；失败 NotRegistered。
- 注册期间非 ACK 数据进入 pending 队列，recv 优先消费。
- 分片：客户端 max_payload=1200；Reassembler total<=4096；Go MaxDatagram=2048。

## 能力链
- RelayClient.register → Go cmd/relay 注册校验 → ACK
- pending 缓存 → recv → Reassembler
- tests：ACK 成功/无 ACK 失败/超限分片；E2E

## 当前证据
- A-10：发送成功即认为注册成功；分片预算 8192 会触发 IP 分片；total 无上限。
- 注册等待 ACK 时对端数据会被丢弃。

## 设计与不变量
- 没有 ACK 一律未注册；重试有次数上限。
- 迟到重复 ACK 用魔数识别并丢弃，不进入重组。
- 注册期间数据不丢：pending 队列按到达顺序回放。
- 分片/包大小有硬上限；未知/超限直接丢弃。
