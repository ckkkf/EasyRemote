# ER-010 路由检查器升级：method + path + auth 语义

## 目标与成熟度
让 `scripts/check-routes.mjs` 不再只比 path：契约端点与代码声明的 method/auth 不一致、代码路由未声明、契约幽灵接口都必须在 --strict 下判红。成熟度：disabled → beta（检查器与代码声明可用；运行时强制方法/鉴权由 ER-012/ER-013 落地）。

## 需求与字段映射
- 字段来源：`docs/spec/contract.yaml` 的 endpoint `method/path/auth`；本卡不改契约。
- 代码声明：新增 `server/internal/{gateway,adminhttp}/route_specs.go`，逐条列出 ID/Method/Path/Auth。
- 字段映射：`RouteSpec.ID <- contract.endpoint id`；`Method <- method`；`Path <- path`；`Auth <- auth`。

## 能力链
- checker：`scripts/check-routes.mjs`（解析契约、代码路由、RouteSpec，输出差异）
- 自测：`scripts/tests/check-routes.test.mjs`（fixture 级 method/auth/path drift）
- 代码声明：`server/internal/httpx/routespec.go` + 两个 route_specs.go
- 运行时：暂由现有 handler 内部鉴权；ER-012 用同一份 RouteSpec 做 method guard/405

## 当前证据
- 旧 checker 只把 `HandleFunc("/path")` 的 path 与 contract path 比集合；method/auth 完全不校验（A-17）。
- 契约 GW-08 声明 POST /v1/connect/status + bearer，实际 handler 是 query GET（ER-013 修）；本卡先让声明与契约一致，防止后续漂移。

## 设计与不变量
- RouteSpec 是代码侧唯一声明；checker 双向核对：契约→声明→已注册 path。
- 路径重复（`/healthz` 在 gateway/admin 各注册一次）按 path 归一；spec 只保留一条。
- 任何一方多/少/方法不同/鉴权不同都是 issue；--strict 任一 issue 退出 1。
- 不解析 handler 内部逻辑推断鉴权（避免脆弱的启发式）；声明与运行时一致性由 ER-012/ER-013 的测试保证。
