# ER-014 Flutter/React 完整保留 Envelope 错误字段

## 目标与成熟度
两端错误对象完整保留 `code/name/message/retryable/trace_id`；UI 展示 trace_id 并可一键复制，`retryable` 决定是否出现重试入口；成功体 `data` 不是对象时不得静默变成空 Map。成熟度：beta。

## 需求与字段映射
- 错误信封（docs/spec/error-codes.md §3）：`code:int, name:string, message:string, retryable:bool, trace_id:string`。
- Flutter `ApiException`：code(name) / name / message / retryable / traceId / statusCode。
- React `ApiError`：已有 code/name/message/retryable/traceId；补复制与重试入口。
- 成功信封 `data` 非对象：抛结构化错误（带 trace_id），禁止静默返回空 Map。

## 能力链
- Flutter：api.dart 解码 → ApiException → `error_view.dart`（复制 trace/重试）→ login/connect 页面
- React：api.ts 解析 → errors.ts 元数据 → ErrorBanner（复制/重试）
- 测试：Dart 单元 + widget；vitest 单元

## 当前证据
- Flutter `ApiException(code,message)` 丢掉 retryable/trace_id；`_decode` 把非 Map data 静默成 `{}`。
- React ApiError 字段齐全，但 ErrorBanner 只显示 trace，没有复制；retryable 未驱动任何重试入口；非信封错误退化成 `Error("请求失败（HTTP x）")`。

## 设计与不变量
- 错误码分支继续用 name 字符串（`AUTH_TOKEN_EXPIRED` 等），不改现有调用方。
- trace_id 只在错误详情中展示/复制，不进日志敏感字段。
- 重试按钮仅当 retryable=true 且调用方提供 onRetry；无 onRetry 时只展示不可点提示。
- 复制通过系统剪贴板（Flutter Clipboard / navigator.clipboard），复制成功给轻提示。
- 非 Map 成功 data 视为契约违规：抛 SRV_INTERNAL 并带 trace_id，避免“成功但数据丢失”。
