# ER-205 重连模型：授权复用、票据轮换、旧路径失效

## 目标与成熟度
授权窗口内重连复用同一 authorized 会话；每次签发票据分配递增代号，旧代号被中继拒绝；关闭后撤销键让旧票据失效。成熟度：beta（5s 拔网恢复 E2E 归 ER-903/ER-900）。

## 需求与字段映射
- relaymgr.Ticket.Epoch；IssueWithEpoch / Verify 解析 5 字段（兼容 4 字段 epoch=0）。
- Redis：er:ticket:epoch:<session>:<device>（INCR + 2h TTL）。
- 网关签发：App.TicketEpochs（生产为 signal.ConsentNotifier）→ IssueWithEpoch。
- 中继：TicketEpochCurrent 校验当前代号；错误/不匹配拒绝；撤销键优先。
- Request：授权窗口内复用 authorized（ER-204）。

## 能力链
- 网关 /v1/relay/ticket → TicketEpochs.Next → IssueWithEpoch
- 中继注册 → Verify → IsSessionRevoked → TicketEpochCurrent → Register
- session.Request 复用 authorized
- tests：授权复用、撤销、轮换

## 当前证据
- 票据无代号：重连重新领票后旧票仍可注册。
- Request 已能复用 authorized，但无重连测试。

## 设计与不变量
- 每次 /v1/relay/ticket 都换新代号；旧代号立即失效（多实例共享）。
- epoch=0 仅单机/开发；生产签发必须带代号（后端不可用则拒绝签票）。
- 中继在校验 HMAC/exp 后依次检查撤销与代号；Redis 错误按拒绝处理（fail-closed）。
- 关闭撤销键永久优先于代号。
