## 当前证据
- `client/test/native_test.dart:100-109`：一次严重反馈后期望降档。
- `core/crates/er-abr/src/lib.rs`：severe 需 `severe_streak >= 2` 才降，违反 PRD 单周期语义；现有单测 `single_cycle_spike_does_not_downgrade`、`sustained_congestion_downgrades` 固化了旧行为。
- `flutter test` 基线：ABR 用例失败（见 ER-000 baseline 日志）。

## 设计与不变量
- severe = loss>8% 或 queue>200：**当周期**降档（仍有 min_interval 防同周期重复降）。
- mild = loss>2% 或 queue>80 或 rtt>250：连续 2 周期才降（保留抗抖动）。
- healthy 升档仍需连续 3 周期；噪声周期只削一格健康计数，不清零。
- 不得删除 `single_cycle_spike` 回归意图：改为验证「严重尖峰按 PRD 当周期降档，但只降一次」，并保留轻度尖峰不降档的用例。
