# ER-602 关键帧请求与有界重组

## 目标与成熟度
丢包/解码失败时主控请求关键帧（≤2 次/秒）；分片重组在途消息有界，避免无限增长。成熟度：beta（30 分钟稳定性/抖动策略未验证）。

## 需求与字段映射
- MSG_KEYFRAME=5：主控请求关键帧；被控流收到后 enc.request_keyframe()。
- should_request_keyframe(last_seq, seq, since_last)：seq 跳变且距上次≥500ms。
- 解码失败也触发关键帧请求（同样节流）。
- Reassembler.inflight_len + 上限 MAX_INFLIGHT=8；超限淘汰最旧。

## 能力链
- ctrl_session 收包/解码 → 请求
- host_stream 收 MSG_KEYFRAME → 编码器关键帧
- wire Reassembler 有界
- tests：keyframe 策略、inflight 上限

## 当前证据
- 无关键帧请求；丢包后画面长期花屏/卡住。
- 无在途消息上限测试。

## 设计与不变量
- 请求必须节流，不能每帧刷。
- 关键帧请求是控制消息（加密），与视频通道独立。
- 重组在途数硬上限；淘汰最旧。
- 不引入无限队列。
