# ER-610 输入有序、ACK 延迟与权限门控

## 目标与成熟度
输入携带序号，被控端按序交付/去重；输入 ACK 回传并统计 P95；坐标映射沿用被控分辨率；输入只在授权后的会话循环注入。成熟度：beta（closed 后输入无效、真实 P95 未做端到端断言）。

## 需求与字段映射
- MSG_INPUT：[MSG_INPUT][seq u32][event]；MSG_INPUT_ACK：[MSG_INPUT_ACK][seq u32]。
- InputSequencer：按 seq 有序交付，重复丢弃，最多缓存 64，超限丢最旧。
- 被控端收到事件后立即 ACK（作为接收确认）。
- 主控 pending seq→Instant，ACK 计算延迟；保留最近 100 样本，P95 上报。
- CtrlStats：input_acks、input_p95_ms；FFI/质量抽屉展示。
- 坐标：UI 按远端帧宽高换算像素；Mac 注入器再做 pixel→point。

## 能力链
- UI pointer → SessionVideo.send → ControllerAgent.send_input
- 被控 InputSequencer → Injector → ACK
- CtrlSession ACK 统计 → FFI → UI

## 当前证据
- 输入无序号/ACK；UDP 乱序可能键鼠错序。
- 无 P95 延迟证据。

## 设计与不变量
- 相同 seq 只注入一次；过期/重复丢弃。
- 乱序窗口有界；不无限缓存。
- ACK 只代表被控端已接收/入队，不代表注入成功；注入失败计入 stats。
- 只有 authorized/active 会话循环才注入；closed 后循环退出。
