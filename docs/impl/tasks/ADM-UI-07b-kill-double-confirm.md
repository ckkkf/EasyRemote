# ADM-UI-07b 强制中断双人确认（缺口卡）

> 状态：**未开始**（缺口卡；由 ADM-UI-00b 复核登记）
> 来源：`docs/spec/pages.md` A9（行 244-246）、PRD §6.3.4（行 606）

## 缺什么

A9 的"双人确认"：高危中断（例如批量中断或高权限目标）需要第二个管理员确认后才能执行。

## 为什么不能现在做

- 需要"待确认中断请求"的持久化模型（发起人 / 确认人 / 过期时间 / 状态），以及第二个人的身份校验；
- 当前 `POST /admin/v1/sessions/kill` 是单次同步调用，加双人确认属于新的工作流，不能在前端伪造。

## 建议拆分

- ADM-API-07b1：`kill_request` 模型 + 发起/确认/过期接口（contract-first）。
- ADM-UI-07b2：确认页/通知入口 + 超时状态展示。

## 验收提示

必须证明"第二个人确认前不会真的中断"，并覆盖过期与撤回路径。

## 进度（ADM-UI-00c 复核）

- 已完成：07b1（后端发起/确认/过期 + 三条审计）、07b2（页面入口 + 待确认列表 + 第二人确认）。
- 仍缺：待确认请求的通知（站内信/IM）、过期清理定时任务。
