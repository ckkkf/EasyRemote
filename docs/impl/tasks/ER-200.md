# ER-200 session 状态机 command + version + CAS

## 目标与成熟度
所有会话迁移只经 session.Apply(Command)：读当前 version → 校验白名单 → CAS 写回；非法迁移拒绝、重复事件幂等、并发 accept/kill 不丢更新。成熟度：beta。

## 需求与字段映射
- store.Session 增加 version:int64（JSON）。
- store.Store 增加 UpdateSessionCAS(ctx, s, expected)；冲突返回 ErrVersionConflict。
- session.Command：Kind(request/consent/activate/close)、SessionID、ControllerID、TargetID、Accepted、Reason、ExpectedVersion。
- 状态迁移表保持不变：requested→authorized/closed；authorized→active/closed；active→closed。

## 能力链
- gateway/admin/signal 调用 session.Service 封装方法（内部 Apply）
- Service.applyTransition：最多 5 次 CAS 重试
- PG：version 列 + WHERE version=$expected；Memory：版本比较
- tests：非法迁移、重复事件、ExpectedVersion、并发、超时收口

## 当前证据
- 旧 Service 直接 Get→改字段→UpdateSession，无版本；并发 accept/kill 可丢更新。
- 旧测试把“重复 kill/activate 必须失败”当契约，违反幂等事件要求。

## 设计与不变量
- 非法迁移不改 state/version。
- 重复 consent(accepted)/activate/kill 返回当前会话且不增加 version。
- CAS 冲突自动重读重放；5 次仍冲突返回 SRV_INTERNAL（可重试）。
- ExpectedVersion>0 与当前不符直接失败（调用方显式并发控制）。
- 超时收口：consent 超时经 CAS 关闭并返回 CONN_CONSENT_TIMEOUT；auth window 过期关闭并返回 SESSION_AUTH_WINDOW_EXCEEDED。
- PG 迁移幂等：ADD COLUMN IF NOT EXISTS version bigint NOT NULL DEFAULT 1。
