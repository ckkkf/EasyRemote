## 0. 文档约定

- **优先级**：P0 = MVP 必须；P1 = V1；P2 = V2 及以后。
- **验收标准**一律数值化，不接受「流畅」「稳定」这类不可测表述。
- **不做清单**（§4.4）与功能清单同等重要。
- 本文所有性能数字必须可复现：给出测试方法，而不是只给结论。

## 1. 背景与目标

### 1.1 问题定义

远控产品用户流失的真实原因，不是「连不上」，而是 **「连上了，但用起来难受」**：

| 现象 | 用户语言 | 技术根因 |
|---|---|---|
| 画面糊 | 「像在看直播」 | 码率不足 / 分辨率被降 / 4:2:0 色度抽样 |
| 卡一下 | 「鼠标跟不上手」 | 编码队列堆积、抖动缓冲过大、拥塞控制迟钝 |
| 突然卡死 | 「用着用着就死了」 | 无重连机制、TCP 队头阻塞 |
| 不知道为啥卡 | 「到底是我网差还是软件差」 | 无质量可视化、无诊断能力 |

**EasyRemote 的第一性目标：让用户随时知道「现在好不好」以及「为什么不好」。**

这不是一句口号，它决定了三个设计：
1. 会话中常驻质量指示器（帧率/延迟/码率），不藏在设置里；
2. 一键网络诊断，输出可读结论（不是一串 IP）；
3. 后台能按设备维度回溯质量，定位是个案还是普遍问题。

### 1.2 目标（12 个月，不含营收）

| 编号 | 目标 | 度量 |
|---|---|---|
| G1 | 建立可用闭环 | Win↔Win 会话成功率 ≥ 97% |
| G2 | 达到「无感」延迟 | 局域网按键到画面 P95 ≤ 40ms；同城公网 P95 ≤ 70ms |
| G3 | 覆盖主流端 | Win / macOS / Android / iOS 四端可互连 |
| G4 | 可运营 | 后台管理系统上线，覆盖用户/设备/会话/风控四类操作 |
| G5 | 问题可定位 | 线上质量问题能在 24h 内定位到根因（网络/编码/客户端 bug） |

### 1.3 非目标

- **不做商业化**：不做会员、不做计费、不做付费墙（本版明确移出）。
- 不做云电脑/云游戏（不提供算力）。
- 不做批量运维编排。
- 不做 Linux 与 Web 端（V2 评估）。
- 不做「隐藏运行 / 静默安装」（安全红线，见 §9.3）。

## 2. 用户画像与场景

| 画像 | 场景 | 关键诉求 | 对「卡」的容忍度 |
|---|---|---|---|
| P1 职场救急 | 家里连公司电脑改文档 | 键盘输入不丢字、滚动不卡 | 低（打字卡一下就想砸键盘） |
| P2 手游玩家 | 手机连家里 PC 玩端游 | 帧率稳定、按键跟手 | 极低（一帧掉就影响操作） |
| P3 家庭技术支持 | 帮爸妈修电脑 | 连得上、看得懂 | 高（能用就行） |
| P4 设计交付 | 外出连工作站看稿 | 色彩准、大图不糊 | 中（能等，但不能糊） |
| P5 移动应急 | 手机取文件 | 快速连、文件能拉下来 | 高 |

**优先级判断**：P1 与 P2 是对「卡」最敏感的两群，也是口碑传播的主力。PRD 的所有性能指标以 **P1 的输入延迟** 和 **P2 的帧率稳定性** 为基准。

## 3. 信息架构（按痛点 B 重做）

### 3.1 首页

```
┌──────────────────────────────────────┐
│ [我的设备]                    [+]     │  ← 设备卡片网格，在线状态优先
│ ┌────────┐ ┌────────┐ ┌────────┐    │
│ │ 公司PC │ │ 家里PC │ │ Mac    │    │
│ │ ● 在线 │ │ ○ 离线 │ │ ● 在线 │    │
│ └────────┘ └────────┘ └────────┘    │
│                                       │
│ [ 输入设备码连接 ]  [ 协助他人 ]       │  ← 次级入口，不做成巨型输入框
└──────────────────────────────────────┘
```

**设计判断**：v0.1 把「大输入框」放首屏是按「痛点 A（连不上）」设计的。既然痛点在 B，首屏就该是**设备卡片**——老用户 1 次点击进会话，把输入框降级为次级入口。

### 3.2 会话中（关键改动）

```
┌────────────────────────────────────────────┐
│ ┌────────────────────────────────────────┐ │
│ │  远端画面                              │ │
│ │                          ┌───────────┐ │ │
│ │                          │ 60fps     │ │ │  ← 质量浮层，常驻可折叠
│ │                          │ 28ms      │ │ │
│ │                          │ 4.2Mbps   │ │ │
│ │                          └───────────┘ │ │
│ └────────────────────────────────────────┘ │
│ [画质▾] [全屏] [文件] [剪贴板] [声音] [⚙] │  ← 桌面常驻工具栏
└────────────────────────────────────────────┘
```

- **质量浮层**：默认显示，可折叠为一个小圆点（绿/黄/红）。颜色规则：绿 = 达标，黄 = 降级中，红 = 严重。
- **点击浮层** → 展开详情：RTT、丢包率、实际码率、编码耗时、解码耗时、当前档位、P2P/中继标识。
- **详情页底部**「网络诊断」按钮 → 跑一轮探测，输出人话结论。

### 3.3 网络诊断输出示例

```
诊断结果：当前使用「中继转发」（P2P 打洞失败）
├─ 你的网络：NAT 类型 = 对称型（Symmetric NAT）
├─ 对方网络：NAT 类型 = 端口受限锥形
├─ 结论：对称 NAT 与多数网络无法直连，已自动走中继
├─ 影响：延迟 +12ms，码率上限 6Mbps
└─ 建议：如在公司网络，可联系网管放行 UDP 3478/443
```

**这是产品差异化的核心**：市面上大多数远控产品只会说「网络不佳」，而用户真正想知道的是「为什么」和「怎么办」。

### 4.2 MVP 范围冻结

**交付**：Win↔Win 全链路 + 账号/信令/中继/后台四套服务。

**必须可用但不打磨**：视觉设计、多语言、崩溃上报详情。

**不做**：移动端、macOS、音频、多屏、按键映射、WOL、协助码、风控中心。

### 4.3 MVP 上线门槛（DoD）

1. 100 次连续建连，成功率 ≥ 97%，P50 建连 ≤ 3s。
2. 1080p@60 连续 30 分钟，无花屏、无累积延迟增长（会话前后延迟差 ≤ 5ms）。
3. 拔网线 5s 恢复后，10s 内自动重连成功。
4. 1GB 单文件传输成功，中断后续传不重传已完成块。
5. 隐私屏开启后被控端本机不可见画面，采集不中断。
6. 被控端拒绝授权时，主控端 100% 无法看到画面。
7. 后台能查到该次会话的记录与质量数据。
8. 质量浮层数据与后台记录一致（误差 ≤ 5%）。

### 4.4 不做清单

- 不做会员、计费、付费墙。
- 不做「静默安装 / 隐藏托盘无感知」——被控必须有显式授权。
- 不做内核级驱动注入（不碰反作弊对抗）。
- 不做远程摄像头 / 麦克风监听。
- 不做跨账号设备码的模糊匹配（错误即锁）。

## 5. 客户端功能规格

> 每条：**用户故事 → 交互流程 → 状态机 → 异常分支 → 验收标准**

### 5.1 连接与会话（P0）

#### 5.1.1 同账号直连（主路径）

**用户故事**：作为老用户，我希望点一下设备卡片就进去，不要输任何码。

**流程**
1. 首页设备卡片 → 点击「公司PC」。
2. 客户端查信令服务该设备在线状态。
3. 在线 → 直接发起 → 被控端弹出**授权确认**（首次/非信任设备）或**直接进入**（已信任设备）。
4. 建立 QUIC 连接 → 打洞 → 首帧。

**信任设备定义**：同账号 + 过去 7 天内成功连接过 + 被控端未撤销信任。信任关系存于被控端本地，服务端只存哈希。

#### 5.1.2 设备码连接（跨账号）

1. 被控端「本机设备」页展示 9 位设备码 + 6 位临时验证码（10 分钟轮换）。
2. 主控端输入 → 查设备 → 输验证码 → 被控端弹授权（显示主控昵称、账号尾号、IP 归属地）。
3. 确认后建连。

**状态机**

```
IDLE → RESOLVING → AUTH_PENDING → CONSENT_PENDING → NEGOTIATING
     → CONNECTED → (RECONNECTING) → CLOSED
任意态 → FAILED(原因码)
```

**异常分支**

| 分支 | 处理 |
|---|---|
| 设备码不存在 | 统一提示「设备不存在或未开启被控」，不区分（防枚举） |
| 验证码错误 | 5 次锁定 30 分钟，锁定期内正确码也不放行 |
| 被控端拒绝 | 24h 内对同设备重试上限 3 次 |
| 被控端 30s 无响应 | 超时失败 |
| 打洞失败 | 自动切中继，用户无感（诊断页可见） |

**验收**
- 同账号直连 P50 ≤ 3s，P95 ≤ 6s。
- 跨账号必须显式授权，拒绝后主控端 100% 不可见画面。

#### 5.1.3 断线重连

- 指数退避 1/2/4/8s，最多 10 次，总计 ≤ 60s。
- 重连成功保留档位与开关状态，**不重新弹授权**（授权在会话生命周期内有效，最长 12h）。
- UI 显示「重连中（3/10）」，超过 3 次自动提示「切换中继」。

**验收**：拔网线 5s 恢复 → 10s 内重连成功 → 画面 2s 内恢复实时。

#### 5.1.4 权限收回

- 被控端悬浮条「正在被 XXX 远程控制」+ 一键断开，**不可被远程关闭**。
- 会话结束可查最近连接记录。

### 5.2 画面与质量（P0）

#### 5.2.1 档位

| 档位 | 分辨率 | 帧率 | 目标码率 |
|---|---|---|---|
| 流畅 | 1280×720 | 30 | 1.5 Mbps |
| 高清（默认） | 1920×1080 | 60 | 4 Mbps |
| 超清 | 2560×1440 | 60 | 8 Mbps |
| 4K（V1） | 3840×2160 | 60/144 | 15–40 Mbps |

- 默认「自适应」，用户可手动锁定；锁定后不再自动降档，但会提示风险。

#### 5.2.2 采集

- Windows：DXGI Desktop Duplication 优先，GDI 兜底。
- 采集帧率与显示器刷新率解耦。
- 光标默认「本地叠加」，可切「远端烧录」。

#### 5.2.3 编码

- 硬编优先：NVENC / QSV / AMF；回退 x264 ultrafast。
- 低延迟预设：无 B 帧、无 lookahead、GOP ≤ 1s。
- 降级链：硬编 → 软编 → 降分辨率 → 降帧率。

#### 5.2.4 自适应码率（ABR）

- 信号：RTT、丢包率、接收端缓冲水位、实际吞吐、编码队列深度。
- 周期 200ms；升档保守（连续 3 周期达标），降档激进（单周期异常即降）。
- 拥塞控制基线用 QUIC 内建（Cubic/BBR 可切），ABR 在其上做码率决策。

**验收**
- 丢包 ≥ 5% 后 2s 内完成降档。
- 带宽恢复后 10s 内回档，1 分钟内切换 ≤ 3 次（防震荡）。

#### 5.2.5 质量浮层与诊断（P0，差异化核心）

**浮层字段**：实时帧率、端到端延迟、当前码率、丢包率、链路类型（P2P/中继）、档位。

**详情展开**：编码耗时、解码耗时、抖动缓冲深度、RTT、NAT 类型、重传率。

**网络诊断**：主动探测（STUN 绑定请求 + 中继回环 + 带宽探测），输出 §3.3 那样的人话结论。

**验收**
- 浮层数据每秒刷新，与后台记录误差 ≤ 5%。
- 诊断 10s 内出结果，结论命中真实原因（人工核对 20 个样本，准确率 ≥ 90%）。

#### 5.2.6 隐私屏（P0）

- 开启后被控端物理屏显示黑屏，采集继续。
- 被控端快捷键 Ctrl+Alt+Shift+Q 立即终止隐私屏并断开。
- 验收：开启后被控端侧拍摄为黑，主控画面正常；关闭 1s 内恢复。

### 5.3 输入（P0）

- 键盘：扫描码级映射（不经字符），支持组合键面板（Ctrl+Alt+Del 等）。
- 输入法：默认「本地输入法直通」（上屏文本注入），可切「远端输入法」。
- 鼠标：绝对定位默认，相对定位供游戏；本地光标 / 远端光标可切。
- CapsLock/NumLock 状态双向同步。

**验收**：连续输入 500 字符无丢字无乱序；同坐标点击 100 次全部命中。

### 5.4 文件传输（P0，降级版）

**MVP 范围**：单文件双向传输 + 断点续传 + 传输队列。
**V1 补充**：目录递归、拖拽、剪贴板文件引用。

- 走 QUIC 可靠 Stream，与媒体通道隔离（可限速）。
- 分块 1–4MB，块级 xxHash64 校验，位图记录完成块。
- 传输前预检磁盘空间；文件名冲突弹窗（覆盖/跳过/重命名）。

**验收**
- 1GB 单文件成功率 100%，续传不重传已完成块。
- 局域网 ≥ 50MB/s（千兆），公网 P2P ≥ 5MB/s。

### 5.5 剪贴板（P0）

| 类型 | MVP | 说明 |
|---|---|---|
| 文本 | ✅ | 上限 1MB |
| 图片 | ✅ | 上限 20MB，PNG |
| 文件引用 | V1 | 走文件通道 |
| 富文本样式 | ❌ | 只保内容 |

- 双向可单独关闭；后写覆盖；来源标记 + 内容哈希去重（防回声）。
- 敏感内容拦截：疑似密钥/密码格式默认不自动同步，需手动确认。

**验收**：文本同步延迟 ≤ 500ms（局域网）；连续 100 次无丢失无重复。

### 5.6 设置与安全（P0）

被控端本地设置（**远程不可改，只能关不能开**）：允许被控（默认关）、每次确认、验证码轮换周期、固定密码（V1）、白名单（V1）、单向远控（V1）、隐私屏默认、剪贴板开关、文件传输开关。

**安全铁律**：任何「允许被控」类开关都不得被远程会话开启，这是架构级约束，不是 UI 约束。

## 6. 后台管理系统（Admin Console）

> **本章为 v0.2 新增，MVP 一级模块。** 没有后台，线上出问题只能靠用户截图，等于瞎飞。

### 6.1 设计原则

1. **后台与客户端 API 完全隔离**：独立域名、独立鉴权、独立数据库账号，客户端拿不到后台任何接口。
2. **所有操作留痕**：谁在什么时候对哪个对象做了什么，永久审计。
3. **敏感操作二次确认**：踢下线、封禁、强制断开会话，必须输入原因并二次确认。
4. **默认只读**：新账号默认只读权限，写权限显式授予。
5. **MFA 强制**：所有后台账号必须开启二次验证（TOTP）。
6. **不做「看画面」功能**：后台**永远**不提供查看用户屏幕内容的能力，架构上中继只转发密文。这条写进代码审查清单。

### 6.2 角色与权限（RBAC）

| 角色 | 权限范围 |
|---|---|
| 超级管理员 | 全部，含账号管理、配置下发、数据导出 |
| 运营 | 用户/设备查询与备注、公告推送、版本发布（需审批） |
| 客服 | 用户/设备查询、会话记录查看、强制断开会话（需填原因） |
| 风控 | 黑名单、封禁、异常告警处理、举报审核 |
| 只读 | 仅查看仪表盘与列表 |

权限粒度到「模块 + 动作」（如 `device.force_offline`、`user.ban`）。

### 6.3 功能模块

#### 6.3.1 仪表盘（P0）

实时看板，5s 刷新：

| 指标组 | 指标 |
|---|---|
| 规模 | 在线设备数、在线用户数、进行中会话数、24h 新增设备 |
| 质量 | 建连成功率、P2P 打洞成功率、中继占比、端到端延迟 P50/P95、平均帧率达成率 |
| 稳定性 | 会话异常中断率、客户端崩溃率、重连成功率 |
| 分端 | 按平台（Win/mac/Android/iOS）、按客户端版本切片 |

图表：24h / 7d / 30d 趋势；支持按平台与版本下钻。

**验收**：指标口径在文档中有唯一定义（见 §6.8），前后端与客户端埋点三处一致，误差 ≤ 1%。

#### 6.3.2 用户管理（P0）

- 搜索：账号 ID / 手机号（脱敏）/ 设备码 / 昵称。
- 详情：注册时间、最近登录、绑定设备列表、历史会话数、封禁状态。
- 操作：封禁（临时/永久，必填原因）、解封、踢下线、备注、重置设备信任。
- 注销请求处理：7 天冷静期内可撤回。

**验收**：手机号默认脱敏（138****8888），查看明文需二次授权并记录审计。

#### 6.3.3 设备管理（P0）

- 搜索：设备码 / 设备名 / 归属账号。
- 详情：设备码、平台、系统版本、客户端版本、最后在线、NAT 类型、历史质量曲线。
- 操作：强制下线、解绑、标记风险设备。
- **设备质量回溯**：选一台设备，看它最近 30 天的会话质量趋势（延迟/丢包/档位/是否走中继）。

**这是客服排查的核心工具**：用户报「卡」，先看这台设备的历史曲线，是个案还是普遍。

#### 6.3.4 会话管理（P0）

- 进行中会话列表：会话 ID、主控设备、被控设备、时长、当前延迟、是否中继。
- **强制中断**（安全应急）：填原因 → 双人确认（可配置）→ 立即断开 → 通知双方。
- 历史会话查询：按时间/账号/设备筛选，看单次会话的质量曲线。

#### 6.3.5 风控中心（P1）

| 能力 | 说明 |
|---|---|
| 异常连接告警 | 同 IP 高频连接不同设备、短时间大量验证码失败 |
| 黑名单 | IP / 设备码 / 账号，支持 CIDR 与有效期 |
| 爆破拦截记录 | 验证码错误锁定事件列表 |
| 举报处理 | 用户举报可疑连接 → 工单 → 处置 |
| 风险评分 | 账号维度的简单规则打分（新注册 + 异地 + 高频 = 高风险） |

#### 6.3.6 版本与分发（P0）

- 客户端版本列表：版本号、平台、发布状态、覆盖率。
- **灰度发布**：按比例（5%/20%/50%/100%）或按账号白名单放量。
- 强制升级策略：低于某版本禁止连接（带提示文案）。
- 下载页配置：安装包地址、更新日志、系统要求。

#### 6.3.7 配置中心（P0）

远程下发、客户端热生效的开关与参数：

| 类别 | 示例 |
|---|---|
| 画质 | 各档位默认码率、帧率上限、ABR 升降档阈值 |
| 连接 | 验证码有效期、授权超时、重连退避次数 |
| 限流 | 单 IP 建连频率、验证码尝试次数 |
| 开关 | 文件传输开关、剪贴板开关、隐私屏开关、诊断开关 |

**要求**：所有配置项有默认值、有变更历史、可一键回滚、可按平台/版本定向下发。

#### 6.3.8 审计日志（P0）

记录字段：操作人、角色、动作、对象、变更前后值、IP、时间、结果。不可删除，只可查询与导出。

**验收**：任意一次「封禁用户」操作可在审计日志中完整还原。

#### 6.3.9 公告与消息（P1）

- 站内公告（客户端弹出）
- 定向推送（按平台/版本/账号）
- 紧急通知（如某版本有严重 bug，强制提示升级）

#### 6.3.10 数据导出（P1）

按模块导出 CSV（用户/设备/会话/风控），导出动作本身进审计。

### 6.4 技术形态

- **前端**：Web 管理台（React/Vue 均可），独立仓库或独立目录。
- **后端**：独立服务，复用同一套业务领域模型但走独立网关。
- **鉴权**：账号密码 + 强制 TOTP；支持 IP 白名单（可选）。
- **部署**：与客户端 API 分域部署，可内网访问（运维专用）。

### 6.5 后台验收（MVP）

1. 能查到任一用户的账号、设备、最近 10 次会话。
2. 能对任一进行中会话执行强制中断，双方 3s 内断开且收到通知。
3. 能发布一个灰度版本并观察到覆盖率变化。
4. 能修改一个配置项并在 30s 内下发到在线客户端。
5. 任一写操作在审计日志中可完整还原。
6. 后台任何界面**不存在**查看用户屏幕内容的入口。

### 6.6 后台不做清单

- 不做查看用户画面/剪贴板/文件内容。
- 不做「远程代操作」（管理员冒充用户操作设备）。
- 不做用户密码明文查看或重置为已知值（只能发重置链接）。
- 不做无审计的批量操作。

## 7. 技术架构

### 7.1 客户端分层

```
┌──────────────────────────────────────────────┐
│ Flutter UI（Win/macOS/Android/TV/iOS）        │
├──────────────────────────────────────────────┤
│ flutter_rust_bridge（FFI，帧走纹理直通）       │
├──────────────────────────────────────────────┤
│ Rust Core                                     │
│  ├─ capture     DXGI / SCK / MediaProjection  │
│  ├─ codec       NVENC/QSV/AMF/VT/MediaCodec   │
│  ├─ transport   ★ 抽象 Transport trait         │
│  │    ├─ QuicTransport（quinn，MVP）            │
│  │    └─ CustomUdpTransport（V2 可替换）        │
│  ├─ nat         STUN/ICE、打洞、Relay 切换      │
│  ├─ input       SendInput / CGEvent / ...     │
│  ├─ fs          文件传输引擎                    │
│  ├─ clipboard   剪贴板桥                        │
│  └─ session     状态机、鉴权、密钥协商          │
├──────────────────────────────────────────────┤
│ 平台原生插件：权限申请、服务/守护、托盘          │
└──────────────────────────────────────────────┘
```

### 7.2 传输层（v0.2 核心变更）

#### 7.2.1 选型

**MVP：QUIC v1（Rust `quinn`）+ DATAGRAM 扩展（RFC 9221）**

| 数据 | 承载方式 | 特性 |
|---|---|---|
| 视频帧 | QUIC DATAGRAM | 不可靠、可丢、低开销、无序 |
| 音频帧 | QUIC DATAGRAM | 同上 |
| 控制指令（输入/信令） | QUIC Stream（单向，短生命周期） | 可靠、有序 |
| 文件传输 | QUIC Stream（双向） | 可靠、有序、可流控 |
| 剪贴板 | QUIC Stream | 可靠 |

**关键设计：帧不排队。** 视频帧进 DATAGRAM 前做「丢弃策略」——编码队列超过阈值时直接丢最旧的帧，而不是排队等发送。这是低延迟的第一原则。

#### 7.2.2 抽象接口（为 V2 自研预留）

传输层必须抽象成 trait，MVP 实现只有 QUIC 一版，但接口设计要满足未来替换：

```
trait Transport {
    async fn open_connection(peer: PeerInfo) -> Result<Connection>;
    async fn send_datagram(ch: ChannelId, data: Bytes) -> Result<()>;
    async fn send_reliable(ch: ChannelId, data: Bytes) -> Result<()>;
    fn stats() -> TransportStats;   // RTT / 丢包 / 带宽估计 / 拥塞窗口
    fn set_bandwidth_limit(limit: BitRate);
}
```

**要求**：上层（会话、ABR、文件）不得直接依赖 `quinn` 类型，只能依赖该 trait。

#### 7.2.3 打洞与中继

```
1. 双方各自向 STUN 服务器取 srflx 候选
2. 通过 Rendezvous 交换候选（含 host / srflx / relay）
3. 并行打洞（超时 3s）：直连成功 → P2P
4. 失败 → 走 Relay（TURN 思路）：QUIC 连接建立到中继，中继只转发密文
5. 会话中持续探测：若发现可直连，热切换到 P2P（V1）
```

**保持能力**：STUN/ICE 候选收集、UDP 打洞、Relay 兜底，三者缺一不可。

#### 7.2.4 后续演进（V2 评估项）

根据真实弱网测试结果，评估是否引入：

- **FEC**：在 DATAGRAM 层加前向纠错，对抗 5–15% 丢包。
- **自适应拥塞控制**：针对视频流量定制（当前 QUIC 内建 Cubic/BBR 面向通用流量）。
- **自研 UDP 引擎**：完全替换 QUIC，换取更细粒度控制。

**触发条件**：若 Spike 与 V1 实测中，弱网场景（丢包 10%）的体验显著劣于自研方案的可达上限，则启动。

### 7.3 服务端拓扑

```
客户端 ──TLS──▶ API Gateway ──┬── Auth/Device（账号、设备码、验证码）
                              ├── Rendezvous（长连接、在线状态、候选交换）
                              ├── Policy（配置下发）
                              └── Admin API（独立域名，管理台专用）
                                        │
                              STUN / Relay（边缘节点，按地域就近）
```

| 服务 | 职责 | 关键约束 |
|---|---|---|
| API Gateway | 统一入口、鉴权、限流 | 与 Admin 分域 |
| Auth/Device | 设备码分配、验证码轮换、设备注册 | Redis 存在线状态 |
| Rendezvous | WebSocket/QUIC 长连接、候选交换 | 有状态，需会话粘性 |
| Relay | QUIC 中继转发 | **只转发密文，不可解密** |
| Policy | 配置与开关下发 | 变更可回滚 |
| Admin API | 管理台后端 | 独立鉴权 + 强制 MFA |

### 7.4 延迟预算（1080p@60，局域网）

| 环节 | 预算 | 备注 |
|---|---|---|
| 采集 | 8 ms | DXGI + GPU 拷贝 |
| 编码 | 6 ms | NVENC 低延迟预设 |
| 网络单向 | 5 ms | LAN RTT 10ms |
| 抖动缓冲 | 8 ms | 自适应 |
| 解码 | 5 ms | 硬解 |
| 渲染 | 8 ms | 60Hz 一帧 |
| **合计** | **≈ 40 ms** | 对齐 G2 |

### 7.5 弱网降级矩阵

| 状况 | 动作 |
|---|---|
| 丢包 0–2% | 维持 |
| 丢包 2–5% | 降码率 20% |
| 丢包 5–10% | 降 720p 或 30fps |
| 丢包 >10% 或 RTT >200ms | 切流畅档 + 加大抖动缓冲 + 浮层变红 |
| 完全断网 | RECONNECTING，保留 UI 快照 |

### 7.6 国内网络特别处理（v0.2 新增）

**问题**：运营商对持续性大流量 UDP 存在识别与限速，晚高峰（20:00–23:00）尤其明显。

**对策**
1. QUIC 走 **UDP 443**，与 HTTPS 同端口，降低被识别概率。
2. 提供 **QUIC over TCP 兜底**（连接建立失败或持续劣化时切换）。
3. 监测「UDP 质量突变」：同一网络下 RTT 突然翻倍而带宽未降 → 判定为 QoS，自动建议切 TCP。
4. 在诊断结论里明确写出「疑似运营商限速」，而不是笼统说「网络差」。

## 8. 技术验证 Spike（3 周）

> **目的**：用最小成本回答一个问题——**能不能做到 1080p@60、端到端 ≤ 40ms**。
> 做不到 → 整个产品假设崩塌，需重新评估方案；做得到 → 剩下都是体力活。

### 8.1 范围（只做这些）

- 两台 Windows 机器
- 采集 → 硬编 → QUIC DATAGRAM → 解码 → 渲染
- 键鼠输入回传
- 无账号、无 UI 设计、无文件传输、无重连

### 8.2 周计划

| 周 | 目标 | 验收 |
|---|---|---|
| W1 | 采集 + 硬编 + 本机回环渲染 | 本机 1080p@60 稳定，编码耗时 ≤ 8ms |
| W2 | QUIC DATAGRAM 传帧 + 硬解渲染 | 局域网两台机器看到画面，延迟可测 |
| W3 | 输入回传 + 延迟基准测试 + 弱网注入 | 输出 §8.3 的完整数据表 |

### 8.3 必须产出的数据

| 场景 | 指标 | 目标 |
|---|---|---|
| 局域网千兆 | 端到端延迟 P50/P95 | ≤ 25 / 40 ms |
| 局域网千兆 | 帧率达成率 | ≥ 98% |
| 公网同城（模拟 RTT 20ms） | 端到端延迟 P95 | ≤ 70 ms |
| 公网跨省（模拟 RTT 60ms） | 端到端延迟 P95 | ≤ 110 ms |
| 丢包 5% | 可懂度（画面无花屏块） | 主观 ≥ 4/5 |
| 丢包 10% | 自动降档是否生效 | 2s 内降档 |
| 连续 30 分钟 | 延迟漂移 | ≤ 5 ms |

### 8.4 测量方法（必须可复现）

- **延迟**：被控端全屏显示毫秒计时器（刷新率锁定 60Hz），主控端用 240fps 相机拍屏幕，逐帧比对时间差。
- **帧率**：渲染侧统计实际呈现帧数。
- **丢包**：`tc/netem` 在中间路由注入，或用 `clumsy`（Windows）。
- 所有数据记录成表格存 `docs/spike/results.md`。

### 8.5 决策点（Spike 结束必须回答）

| 判断 | 后续动作 |
|---|---|
| 达成全部目标 | 按 §4.1 进 MVP |
| 延迟达标但弱网差 | 引入 FEC，V2 评估自研 |
| 延迟不达标（>60ms LAN） | 停下来重新评估：是编码、传输还是渲染的问题 |
| QUIC 开销过大 | 评估自研 UDP 或换 DATAGRAM 参数 |

### 8.6 Spike 不做的事

- 不做 UI（用命令行参数 + 一个全屏窗口即可）
- 不做鉴权（固定密钥写死）
- 不做跨平台（只 Win↔Win）
- 不做异常处理（崩了就重启）

## 9. 安全与合规

### 9.1 安全设计

| 层 | 措施 |
|---|---|
| 传输 | 信令 TLS 1.3；媒体端到端加密（X25519 ECDH + ChaCha20-Poly1305），密钥仅两端持有 |
| 中继 | 只转发密文，**架构上无法解密**（这条同时是产品承诺与技术约束） |
| 身份 | 设备证书 + 账号；设备码 ≠ 身份凭证 |
| 授权 | 被控端显式确认 + 验证码 + 白名单（V1）三重 |
| 防爆破 | 设备码与验证码双维度限流 + 错误锁定 + IP 风控 |
| 防枚举 | 设备码空间 10^9；查询响应时间恒定（防时序侧信道） |
| 防重放 | 信令带 nonce + 时间窗 |
| 数据 | 不上传画面；剪贴板与文件内容不落盘服务端；日志脱敏 |

### 9.2 合规清单（需法务确认）

1. 官网与账号系统备案（ICP）。
2. PIPL：设备信息、IP、日志的收集需明示同意；提供注销与数据导出。
3. 网络安全法：日志留存 ≥ 6 个月。
4. 反诈要求：被控端可见指示、一键断开、禁止静默运行。

### 9.3 反滥用（产品红线）

- 被控端**始终**有可见指示（托盘变色 + 会话中悬浮条）。
- 主控端 IP 归属地展示给被控端。
- 首次被陌生账号连接需二次确认。
- 禁止隐藏模式、静默安装、无提示自启。
- 提供「一键举报可疑连接」。
- **后台不得提供查看用户屏幕的能力**（§6.1 第 6 条）。

**唯一现在就要做的事**：把「P2P 命中率」当作一等埋点指标。它同时决定体验和未来成本，晚补不如早埋。

## 11. 里程碑与排期

| 阶段 | 周期 | 交付 | 出口条件 |
|---|---|---|---|

## 13. 度量与验收

### 13.1 核心指标

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| 建连成功率 | 发起连接中被控端可见画面比例 | ≥ 97% |
| 建连时延 | 点击到首帧 | P50 ≤ 3s，P95 ≤ 6s |
| 操作延迟 | 按键到画面变化 | LAN P95 ≤ 40ms |
| 帧率达成率 | 实际/目标 | ≥ 95% |
| P2P 命中率 | 直连成功/总连接 | ≥ 70%（观察项） |
| 会话异常中断率 | 30 分钟内非主动断开 | ≤ 0.2 次/会话 |
| 崩溃率 | 会话中崩溃 | ≤ 0.1% |
| 问题定位时长 | 线上质量问题的根因定位 | ≤ 24h |

### 13.2 验收方法

- 延迟：高帧率相机拍屏逐帧比对（可复现）。
- 弱网：`tc/netem` 或 `clumsy` 注入，跑 §7.5 矩阵。
- 安全：§9 逐条 + 后台「不可查看画面」的代码审查。
- 后台：§6.5 六条手工验收。

## 15. 待评审问题

1. **后台是否需要「多租户/组织」概念**？当前按单租户（全平台一套）设计，若未来做企业版需重构权限模型。
2. **强制中断会话是否需要双人确认**？当前设计为「可配置」，默认单人 + 填原因。
3. **Spike 的 3 周是否包含 Relay 搭建**？当前计划里 Relay 放在 MVP-W3，Spike 只做局域网 + 简单公网。
4. **Windows 最低支持版本**：Win7 还是 Win10？Win7 会显著增加采集与编码的兼容成本。
5. **是否需要 macOS 版本的签名与公证预算**（Apple Developer Program $99/年）？
6. **后台管理台的技术栈**是否需要与客户端统一（Flutter Web）还是有 Web 前端同学？
