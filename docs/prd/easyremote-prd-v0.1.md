## 1. 背景与目标

### 1.1 为什么做

远控赛道被 UU 远程用「核心功能永久免费」重新定义了价格锚点，导致：

- 传统付费远控（向日葵、ToDesk 付费档）价值主张被迫下移；
- 用户对「4K 高帧 + 手机玩 PC」形成预期，做不出这个体验就没有入场资格；
- 免费产品的技术门槛反而是**成本门槛**——中继带宽谁自建谁才有毛利。

EasyRemote 的机会点：**在 UU 的薄弱侧切入**（无 Linux、无 Web、企业能力浅、技术不透明）。

### 1.2 产品目标（12 个月）

| 编号 | 目标 | 度量 |
|---|---|---|
| G1 | 建立可用闭环 | Win↔Win 会话成功率 ≥ 97% |
| G2 | 达到「无感」延迟 | 局域网按键到画面 P95 ≤ 40ms；同城公网 P95 ≤ 70ms |
| G3 | 覆盖主流端 | Win / macOS / Android / iOS 四端可互连 |
| G4 | 建立付费转化能力 | 会员页上线，付费转化率 ≥ 1.5% |
| G5 | 成本可控 | 中继带宽成本 ≤ 单用户 ARPU 的 40% |

### 1.3 非目标（本期明确不做）

- 不做云电脑/云游戏（不提供被控端算力）。
- 不做无人值守的「批量运维编排」能力（仅企业版预留）。
- 不做跨端剪贴板里的富文本样式保真（只保内容）。
- 不做 Linux 与 Web 端（V2 评估）。

## 3. 核心用户旅程（信息架构）

```
启动
 ├─ 未登录 → 登录/注册（手机号+验证码 / 第三方）
 └─ 已登录
     ├─ 本机设备页（展示本机设备码 + 临时验证码 + 允许被控开关）
     ├─ 设备列表页（同账号设备，在线状态，一键连接）
     ├─ 连接页（输入设备码 / 协助码）
     └─ 会话中（工具栏：画质、多屏、文件、剪贴板、声音、输入模式、全屏、断开）
```

**关键原则**：从「打开 App」到「看见对方桌面」≤ 3 次点击 / ≤ 8 秒（同账号场景）。

### 4.2 MVP 范围冻结（本 PRD 的交付边界）

**必须交付**：Win↔Win 全链路（连接、画面、键鼠、文件、剪贴板、隐私屏、重连）+ 账号服务 + 信令服务 + 中继服务。

**必须可用但不打磨**：UI 视觉、多语言、日志上报。

**MVP 明确不做**：移动端、macOS、音频、多屏、按键映射、WOL、计费。

### 4.3 上线门槛（MVP DoD）

1. 100 次连续建连，成功率 ≥ 97%，P50 建连 ≤ 3s。
2. 1080p@60 连续 30 分钟会话，无花屏、无累积延迟增长。
3. 拔网线 5s 后恢复，会话 10s 内自动重连成功。
4. 文件传输 1GB 单文件成功，中断后可续传。
5. 隐私屏开启后被控端本机不可见画面，采集不中断。
6. 被控端拒绝授权时，主控端 100% 无法看到画面（安全用例）。

### 4.4 不做清单（防蔓延）

- 不做「免安装绿色版」以外的分发形态。
- 不做 UE4/UE5 游戏专用的内核级反作弊对抗（不碰内核驱动）。
- 不做远程摄像头、远程麦克风监听。
- 不做「静默安装 / 隐藏托盘无感知」——所有被控必须有一次显式授权。
- 不做跨账号的「设备码猜测」容错（错误即锁）。

## 5. 功能规格

> 每条规格格式：**用户故事 → 交互流程 → 状态机 → 异常分支 → 验收标准**。

### 5.1 连接与会话（P0）

#### 5.1.1 设备码连接

**用户故事**：作为主控用户，我希望输入对方 9 位设备码 + 6 位临时验证码就能连上，不需要配置网络。

**交互流程**
1. 被控端「本机设备」页展示：9 位设备码（固定，随账号绑定）+ 6 位临时验证码（默认 10 分钟轮换）。
2. 主控端输入设备码 → 客户端向信令服务查询该设备在线状态。
3. 在线 → 提示输入验证码；离线 → 提示「设备离线」并给「尝试远程开机」（V1）。
4. 校验通过 → 被控端弹出**授权确认弹窗**（显示主控端昵称、账号尾号、IP 归属地）→ 用户点「接受」。
5. 建立媒体通道 → 显示对方桌面。

**状态机**

```
IDLE → RESOLVING(查设备) → AUTH_PENDING(等验证码) → CONSENT_PENDING(等被控端确认)
     → NEGOTIATING(打洞/选路) → CONNECTED → (RECONNECTING) → CLOSED
任意态 → FAILED(带原因码)
```

**异常分支**

| 分支 | 处理 |
|---|---|
| 设备码不存在 | 统一提示「设备不存在或未开启被控」，不区分（防枚举） |
| 验证码错误 | 累计 5 次锁定该设备码 30 分钟；错误次数写入风控 |
| 被控端拒绝 | 主控端提示「对方已拒绝」，24h 内不可对同设备重试超过 3 次 |
| 被控端超时未响应 | 30s 超时，自动失败 |
| 打洞失败 | 自动切中继，用户无感（仅网络诊断页可见） |

**验收标准**
- 同账号设备：免验证码直连，P50 建连 ≤ 3s，P95 ≤ 6s。
- 跨账号设备码：必须经过被控端显式授权，拒绝后主控端 100% 不可见画面。
- 验证码错误 5 次后锁定生效，锁定期内正确验证码也不放行。

#### 5.1.2 会话中控制

- 工具栏常驻：画质档位、全屏、多屏（V1）、文件、剪贴板开关、声音（V1）、输入模式、断开。
- 被控端**始终**有一个悬浮指示（「正在被 XXX 远程控制」+ 一键断开），不可被远程关闭。
- 主控端主动断开 → 被控端提示「会话已结束」。

#### 5.1.3 断线重连

- 网络抖动 → 客户端进入 RECONNECTING，UI 显示「重连中（3/10）」。
- 重连策略：指数退避 1s/2s/4s/8s，最多 10 次，总计 ≤ 60s。
- 重连成功 → 恢复原会话（保留画质档位、剪贴板开关），**不重新弹授权**（授权在会话生命周期内有效，最长 12h）。
- 重连失败 → 结束会话并提示原因。

**验收标准**：拔网线 5s 恢复后，10s 内自动重连成功且画面在 2s 内恢复为实时。

#### 5.1.4 会话结束与权限收回

- 被控端任一方断开即终止，媒体通道立即销毁密钥。
- 会话结束后，被控端可查看「最近连接记录」（时间、主控账号、时长）。

### 5.2 账号与设备（P0）

#### 5.2.1 账号

- 注册/登录：手机号 + 短信验证码（主）；第三方登录（V1）。
- 账号安全：异地登录提醒、设备管理（踢下线）、注销账号（7 天冷静期）。
- **不需要实名**：远控不属于需实名的内容类服务（法务复核）。

#### 5.2.2 设备列表

| 字段 | 说明 |
|---|---|
| 设备名 | 默认「用户名-设备类型」，可改 |
| 在线状态 | 在线 / 离线 / 忙（正在被控或主控） |
| 设备码 | 同账号可见 |
| 最后在线时间 | 用于判断是否可 WOL |
| 别名与分组 | V1 |

**交互**：设备卡片点击 → 直接发起连接（同账号免验证码）。长按 → 重命名 / 移除 / 查看详情。

**验收标准**
- 设备上下线状态变化在 5s 内同步到其他端（长连接推送）。
- 移除设备后，该设备不再出现在列表且无法免密连接。

#### 5.2.3 被控权限开关

被控端本地设置（**仅本机可改，远程不可改**）：

- 允许被远程控制（总开关，默认关）
- 需要每次确认（默认开）
- 允许的账号白名单（V1）
- 禁止反向控制（单向远控，V1）

> **安全铁律**：任何「允许被控」的开关都不得被远程会话修改。远程会话内只能**关闭**，不能**开启**。

### 5.3 画面（P0）

#### 5.3.1 画质档位

| 档位 | 分辨率 | 帧率 | 目标码率 | 适用 |
|---|---|---|---|---|
| 流畅 | 1280×720 | 30 | 1.5 Mbps | 弱网、移动流量 |
| 高清 | 1920×1080 | 60 | 4 Mbps | 默认（MVP） |
| 超清 | 2560×1440 | 60 | 8 Mbps | 办公/设计 |
| 4K | 3840×2160 | 60/144 | 15–40 Mbps | V1 |

- 默认策略：**自适应**（按 RTT/丢包/带宽探测自动升降档），用户可手动锁定。
- 被控端物理分辨率低于档位 → 按物理分辨率上限采集，不放大。

#### 5.3.2 采集

- Windows：DXGI Desktop Duplication 优先，失败回退 GDI；多 GPU/混合显卡场景需正确处理。
- 采集帧率与显示器刷新率解耦（可降到编码帧率，避免空转耗电）。
- 光标：默认「本地光标叠加」（低延迟）；可切「远端光标烧录」（画面一致性好）。

#### 5.3.3 编码

- 优先硬件：NVIDIA NVENC / Intel QSV / AMD AMF；无硬编回退 x264 ultrafast。
- 编码参数：低延迟模式（无 B 帧、无 lookahead、GOP 可短至 1s）。
- 编码器不可用时降级顺序：硬件 → 软件 → 降分辨率/帧率。

#### 5.3.4 自适应码率（ABR）

- 输入信号：RTT、丢包率、接收端缓冲水位、实际吞吐。
- 决策周期：200ms。
- 升档保守（连续 3 个周期达标才升），降档激进（单周期异常即降）。
- 拥塞控制：基于延迟梯度（类 GCC 思路）+ 丢包补偿。

**验收标准**
- 从 1080p@60 降到 720p@30 在丢包 ≥ 5% 后 2s 内完成。
- 带宽恢复后 10s 内回到目标档位且无震荡（1 分钟内档位切换 ≤ 3 次）。

#### 5.3.5 多显示器（V1）

- 被控端有多显示器时，主控端可切换「显示器 1/2/…」。
- 支持「全部拼接」视图（把多屏拼成一张大画布）。
- 验收：切换显示器 ≤ 1.5s 完成且不重建会话。

#### 5.3.6 隐私屏（P0）

- 开启后，被控端**物理显示器**显示黑屏/自定义提示图，但采集继续（用虚拟显示或独占捕获）。
- 被控端可用快捷键（Ctrl+Alt+Shift+Q）立即终止隐私屏并断开。
- 验收：开启后被控端侧拍摄屏幕为黑，主控端画面正常；关闭后 1s 内恢复。

#### 5.3.7 真彩模式（V1）

- 编码切 4:4:4（硬件支持时）或提高码率补偿色度抽样损失。
- 关闭色调映射/自动亮度调整，输出 sRGB 原值。
- 验收：与本地截图对比，色差 ΔE2000 平均值 ≤ 2。

### 5.4 输入（P0）

#### 5.4.1 键盘

- 键位映射：主控键盘事件 → 平台扫描码 → 被控端对应扫描码（不经过字符，避免输入法冲突）。
- 组合键透传：Ctrl+Alt+Del、Alt+Tab、Win 键等系统组合键需提供「发送快捷键」面板（点击发送，不拦截本地）。
- 输入法：默认「本地输入法直通」（主控端输入法上屏后以文本方式注入被控端）；可切「远端输入法」（直接透传按键，由被控端输入法处理）。
- 特殊键：CapsLock/NumLock 状态同步（避免状态错位）。

**验收标准**：连续输入 500 字符无丢字、无乱序；CapsLock 状态在主被控两端一致。

#### 5.4.2 鼠标

- 绝对定位（默认）：主控端光标位置映射到被控端坐标，避免指针漂移。
- 相对定位：游戏场景用（原始鼠标输入，不做加速）。
- 鼠标模式：本地光标（低延迟）vs 远端光标（画面一致）。
- 多显示器：跨屏切换需正确换算坐标系。

**验收标准**：1080p 下点击目标命中率 100%（同一坐标点击 100 次全部命中）；快速甩动无越界。

#### 5.4.3 触控（P1，Android/iOS 主控）

手勢映射表：

| 手势 | 行为 |
|---|---|
| 单指拖动 | 鼠标移动 |
| 单指点击 | 左键单击 |
| 双指点击 | 右键单击 |
| 双指拖动 | 滚轮滚动 |
| 双指捏合 | 缩放（本地画面缩放，非远端） |
| 三指下滑 | 唤出本地工具栏 |
| 长按 0.5s 后拖动 | 左键拖拽 |

**验收标准**：手势识别准确率 ≥ 95%（各 100 次测试）；误触发率 ≤ 2%。

#### 5.4.4 手柄与按键映射（V1）

- 手柄：XInput / DualShock / DualSense，映射为标准 Xbox 布局；支持直通（被控端识别为手柄）与映射（转为键鼠）。
- 按键映射：手机端浮层虚拟按键 → 映射到扫描码；方案库按游戏名索引。
- 验收：主流手柄即插即用；映射方案可导入导出。

### 5.5 文件传输（P0）

**用户故事**：作为主控用户，我希望在两台机器之间拖拽或选择文件互传，不受大小与类型限制。

**交互**
1. 会话工具栏「文件」→ 打开双栏文件管理器（本地 / 远端）。
2. 支持：拖拽上传/下载、右键菜单（下载、上传、删除、重命名、新建文件夹）、多选。
3. 顶部传输队列：进度、速度、剩余时间、暂停/继续/取消。

**技术规格**
- 独立可靠传输通道（不复用媒体通道），与画面互不抢占带宽（可配置限速）。
- 分块传输（建议 1–4MB/块），块级校验（xxHash64），支持断点续传（记录已完成块位图）。
- 大文件流式写入，不整文件驻留内存。
- 目录递归传输保留相对路径。
- 中文/特殊字符路径正确处理（UTF-8）。

**异常分支**

| 分支 | 处理 |
|---|---|
| 磁盘空间不足 | 传输前预检，提前拒绝并提示所需空间 |
| 文件名冲突 | 弹窗：覆盖/跳过/重命名 |
| 网络中断 | 保留断点，重连后询问「继续传输」 |
| 权限不足 | 提示具体路径，不静默失败 |

**验收标准**
- 1GB 单文件传输成功率 100%，中断后续传不重传已完成块。
- 局域网吞吐 ≥ 50MB/s（千兆环境）；公网 P2P ≥ 5MB/s。
- 1000 个小文件（总 200MB）传输不卡死 UI，进度更新 ≥ 2 次/秒。

### 5.6 剪贴板同步（P0）

**范围**

| 类型 | MVP | 说明 |
|---|---|---|
| 文本 | ✅ | 单次上限 1MB，超出截断并提示 |
| 图片 | ✅ | 上限 20MB，PNG 无损 |
| 文件（复制文件路径引用） | V1 | 大文件走文件传输通道，剪贴板只传引用 |
| 富文本样式 | ❌ | 只保内容，不保格式 |

**策略**
- 方向：双向（可在工具栏单独关闭某一方向）。
- 冲突：后写覆盖；被控端有「剪贴板同步时提示」开关。
- 敏感数据保护：检测到疑似密码/密钥格式（如连续 32 位十六进制、`-----BEGIN` 头）时，被控端默认**不自动同步**，需手动确认。
- 循环抑制：以来源标记 + 内容哈希去重，避免 A→B→A 回声。

**验收标准**
- 文本复制到对端粘贴延迟 ≤ 500ms（局域网）。
- 连续复制 100 次不同内容，无丢失、无重复粘贴。
- 关闭同步后，任何方向均不再传输（抓包验证）。

### 5.7 音频（V1）

- 双向：被控端系统声音 → 主控端播放（默认开）；主控端麦克风 → 被控端（默认关，需显式开启）。
- 编码：Opus，48kHz，单声道/立体声自适应，码率 32–128kbps。
- 延迟预算：≤ 60ms 端到端；与视频做唇音同步（±40ms）。
- 验收：音乐播放无爆音；语音通话可懂度主观评分 ≥ 4/5。

### 5.8 远程开机（V1）

**前置条件**（必须在 UI 里引导，不能只写文档）
1. 被控机 BIOS 开启 Wake-on-LAN；
2. 网卡属性勾选「允许此设备唤醒计算机」+「只允许幻数据包」；
3. 被控机与一台「常在线设备」在同一局域网（作为唤醒代理），或路由器配置端口映射。

**流程**
1. 主控端在设备列表看到「离线（可唤醒）」标记。
2. 点击唤醒 → 请求发往同账号下**同局域网的在网设备**（唤醒代理）→ 代理发魔术包。
3. 无代理时，走云侧「定向唤醒」通道（需要用户提前配置路由器端口映射，UI 提供图文引导）。

**异常**
- 无代理且未配置端口映射 → 明确提示「当前网络无法远程唤醒」+ 引导链接。

**验收标准**：具备代理条件下，唤醒成功率 ≥ 95%，从点击到设备上线可见 ≤ 60s。

### 5.9 设置与安全（P0）

#### 5.9.1 安全设置（被控端本地）

| 项 | 默认 | 说明 |
|---|---|---|
| 允许被控 | 关 | 总开关 |
| 每次连接需确认 | 开 | 关闭后仅白名单可连 |
| 临时验证码轮换 | 10 分钟 | 可设置 1/10/30 分钟 |
| 固定密码 | 无 | 可设，用于无人值守 |
| 设备白名单 | 空 | 仅白名单账号可连接（V1） |
| 单向远控 | 关 | 开启后本机只做主控（V1） |
| 隐私屏默认 | 关 | 可设为「连接即开启」 |
| 剪贴板同步 | 开 | 可单方向关闭 |
| 文件传输 | 开 | 可禁用 |

#### 5.9.2 审计与日志

- 本地保留最近 200 条连接记录（时间、对端账号尾号、时长、传输量）。
- 日志脱敏：不记录画面内容、不记录剪贴板内容、不记录文件内容。
- 崩溃日志可关闭上报（默认开，需明示）。

#### 5.9.3 安全验收（红队项）

1. 中间人：伪造中继节点无法解密媒体流（密钥不在中继落地）。
2. 重放：录制信令报文重放无法建立会话（nonce + 时间窗）。
3. 枚举：连续查询 1000 个不存在设备码，服务端必须限流且响应时间无差异（防时序侧信道）。
4. 越权：主控端 A 无法在未授权情况下读取设备 B 的剪贴板/文件列表。
5. 提权：被控端普通用户无法通过远程会话修改安全设置或开启被控。

## 6. 技术架构

### 6.1 客户端分层

```
┌─────────────────────────────────────────────┐
│ Flutter UI（Win/macOS/Android/TV/iOS）       │  界面、手势、设置
├─────────────────────────────────────────────┤
│ flutter_rust_bridge（FFI 桥）                │  异步消息 + 流式帧回调
├─────────────────────────────────────────────┤
│ Rust Core                                    │
│  ├─ capture   平台采集（DXGI/SCK/MediaProjection）│
│  ├─ codec     硬编解码抽象（NVENC/QSV/AMF/VT/MediaCodec）│
│  ├─ transport UDP 可靠传输 + FEC + ABR        │
│  ├─ nat       STUN 打洞 / TURN 中继切换        │
│  ├─ input     注入（SendInput/CGEvent/...）    │
│  ├─ fs        文件传输引擎                     │
│  ├─ clipboard 剪贴板桥                         │
│  └─ session   会话状态机、鉴权、密钥协商        │
├─────────────────────────────────────────────┤
│ 平台原生插件（少量）：权限申请、服务/守护、托盘   │
└─────────────────────────────────────────────┘
```

**为什么这样切**：采集与注入天生是平台 API，必须落在原生；传输与编码是性能核心，必须落在 Rust；UI 是迭代最快的部分，用 Flutter 一套代码覆盖五端。三者用 FFI 桥连接，**帧数据走零拷贝共享内存/纹理直通**，不经过 Dart 层。

### 6.2 服务端拓扑

```
                    ┌──────────────┐
   客户端 ──TLS──▶  │  API Gateway │  ← 账号/设备/配置/计费
                    └──────┬───────┘
                           │
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
 ┌────────────┐    ┌────────────┐    ┌────────────┐
 │ Auth/Device│    │ Rendezvous │    │  Policy    │
 │  账号与设备 │    │ 信令/在线状态│    │ 画质档位下发 │
 └────────────┘    └─────┬──────┘    └────────────┘
                          │ 交换 SDP 式候选 + 鉴权票据
                          ▼
                  ┌───────────────┐
                  │ STUN / TURN   │  ← 边缘节点，按地域就近
                  │  （中继转发）  │
                  └───────────────┘
```

| 服务 | 职责 | 技术建议 |
|---|---|---|
| API Gateway | 统一入口、鉴权、限流 | 任意（Go/Rust/Node 均可） |
| Auth/Device | 账号、设备注册、设备码分配、验证码轮换 | 关系库 + Redis |
| Rendezvous（信令） | 长连接（WebSocket/QUIC）、在线状态、候选交换 | 有状态服务，需水平扩展 + 会话粘性 |
| STUN/TURN | NAT 类型探测、中继转发 | 自建（coturn 思路），边缘多节点 |
| Policy | 画质/帧率/并发策略下发（会员分层） | 配置中心 |

### 6.3 协议设计（草案）

**分三条通道**：

| 通道 | 传输 | 特性 |
|---|---|---|
| 控制通道（signaling/control） | WebSocket over TLS（建连期）/ 媒体通道内嵌（会话期） | 可靠、有序、低频 |
| 媒体通道（video） | UDP，自研可靠+部分可靠 | 低延迟、可丢、FEC |
| 数据通道（file/clipboard） | UDP 可靠流（或在 TCP 上兜底） | 可靠、有序、可限速 |

**握手序列**

```
1. 主控 → Rendezvous: HELLO {device_code, client_info}
2. Rendezvous → 被控: PUNCH_NOTIFY {controller_info}
3. 被控 → 主控: CONSENT_REQUIRED → 用户确认 → CONSENT_OK
4. 双方: 交换 {stun_candidates, turn_candidates}
5. 打洞尝试（并行，超时 3s）→ 成功则 P2P；失败切 TURN
6. 密钥协商（X25519 ECDH + HKDF）→ 会话密钥
7. 通道建立：video / data / control
8. 心跳 1s（无数据时），3 次丢失判定断线
```

**消息编码**：protobuf（控制/数据）+ 自定义二进制头（媒体，避免解析开销）。

### 6.4 延迟预算（1080p@60，局域网目标）

| 环节 | 预算 | 说明 |
|---|---|---|
| 采集 | 8 ms | DXGI 复制 + GPU 拷贝 |
| 编码 | 6 ms | NVENC 低延迟预设 |
| 网络（单向） | 5 ms | 局域网 RTT 10ms |
| 抖动缓冲 | 8 ms | 自适应，弱网可升到 40ms |
| 解码 | 5 ms | 硬解 |
| 渲染 | 8 ms | 60Hz 一帧 |
| **合计** | **≈ 40 ms** | 与 G2 目标一致 |

> 公网同城 P2P 追加 RTT 增量约 20–30ms，总 60–70ms；跨省 80–120ms 属正常。

### 6.5 弱网降级矩阵

| 网络状况 | 动作 |
|---|---|
| 丢包 0–2% | 维持，FEC 轻度冗余 |
| 丢包 2–5% | 降码率 20%，FEC 加强 |
| 丢包 5–10% | 降分辨率到 720p 或降帧到 30 |
| 丢包 >10% 或 RTT >200ms | 切「流畅」档 + 提高抖动缓冲 + 提示用户 |
| 完全断网 | 进入 RECONNECTING，保留 UI 快照 |

### 6.6 可观测性

- 客户端埋点：建连阶段耗时、打洞/P2P 成功率、档位切换、卡顿次数、崩溃。
- 服务端指标：信令 QPS、在线设备数、中继带宽、TURN 分配成功率。
- **端到端质量指标**：每秒采样实际帧率、RTT、丢包，会话结束后聚合上报（脱敏，不含画面）。

## 7. 安全与合规

### 7.1 安全设计

| 层 | 措施 |
|---|---|
| 传输 | 全通道 TLS 1.3（信令）+ 媒体层端到端加密（ChaCha20-Poly1305，密钥仅两端持有） |
| 身份 | 账号密码/OAuth + 设备证书；设备码 ≠ 身份凭证 |
| 授权 | 被控端显式确认 + 验证码 + 白名单三重 |
| 防爆破 | 设备码 + 验证码双维度限流；错误锁定；异常 IP 风控 |
| 防枚举 | 设备码空间足够大（9 位 = 10^9），且查询响应时间恒定 |
| 隐私 | 隐私屏、剪贴板敏感内容拦截、日志脱敏、不上传画面 |
| 抗攻击 | 中继节点不可解密媒体；信令报文防重放 |

### 7.2 合规要点（需法务确认，PRD 只列清单）

1. **软件著作权与 ICP/EDI**：官网与账号系统需备案。
2. **个人信息保护法（PIPL）**：收集设备信息、IP、日志需明示同意；提供注销与数据导出。
3. **网络安全法**：日志留存 ≥ 6 个月；配合监管取证的能力（仅限法定情形）。
4. **未成年人保护**：远控产品不属内容类，但需在协议中禁止用于监护侵害。
5. **反诈与滥用防控**：必须内置「被控端可见指示 + 一键断开 + 禁止静默运行」，这是**产品红线**，也是监管关注点。
6. **密码法/商用密码**：如使用国密算法需合规评估（当前方案用国际算法，出海与国内均通用）。

### 7.3 反滥用设计（必须写进产品，不是可选项）

- 被控端**始终**有可见指示（托盘图标变色 + 会话中悬浮条）。
- 主控端 IP 归属地展示给被控端。
- 首次被陌生账号连接需二次确认（弹窗显示「这不是你认识的人？」）。
- 禁止任何形式的「隐藏模式」「静默安装」「开机自启且无提示」。
- 提供「一键举报可疑连接」。

## 8. 成本模型

### 8.1 带宽成本（自建中继）

| 场景 | 码率 | 单会话月流量（按 20h/月） | 单价假设 | 单会话成本 |
|---|---|---|---|---|
| 1080p@60 办公 | 4 Mbps | 36 GB | ¥0.5/GB（云带宽折合） | ≈ ¥18 |
| 720p@30 弱网 | 1.5 Mbps | 13.5 GB | ¥0.5/GB | ≈ ¥6.8 |
| 4K@60 设计 | 20 Mbps | 180 GB | ¥0.5/GB | ≈ ¥90 |

> **关键杠杆是 P2P 命中率**。P2P 命中 80% 时，中继成本降至 1/5。因此 NAT 穿透优化是**成本工程**，不只是体验工程。

### 8.2 成本控制手段

1. 提升 P2P 成功率（多 STUN、IPv6 优先、端口预测）。
2. 免费档限制峰值码率（如 4 Mbps），会员档才放开。
3. 中继节点按地域调度，避免跨区回源。
4. 空闲会话自动降帧（无输入 30s 后降到 5fps）。

### 8.3 盈亏线（粗算）

- 尊享 ¥9.9/月，假设中继成本 ¥5/用户/月（P2P 命中 70%），毛利约 50%。
- 免费用户成本必须靠 P2P 命中率压到 ¥1 以内，否则规模越大亏损越大。

## 11. 度量与验收

### 11.1 核心指标

| 指标 | 定义 | 目标（MVP） |
|---|---|---|
| 建连成功率 | 发起连接中被控端可见画面的比例 | ≥ 97% |
